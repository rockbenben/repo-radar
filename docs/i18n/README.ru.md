# repo-radar

> Проект 365 Open Source #027 · Локальная панель Git-репозиториев — сквозная очередь действий, отвечающая на вопрос, что требует вашего внимания прямо сейчас.

Локальная панель для всех Git-репозиториев на вашей машине: сканирует каждый репозиторий и выводит на первый экран самое важное — сквозную **очередь действий**, отвечающую на вопрос *что требует вашего внимания прямо сейчас* — кликните на пункт и сразу перейдите к действию. Интерфейс построен на antd 6 в глубокой теме «приборной панели пилота».

## Быстрый старт

```bash
npm install
npm run build   # сборка фронтенда
npm start       # http://localhost:7420
```

При первом запуске создаётся конфигурация по умолчанию в `~/.repo-radar/config.json`. Отредактируйте `roots`, добавив каталоги, которые нужно сканировать (например, `D:\Projects` — в JSON обратные слэши нужно экранировать как `D:\\Projects`), затем нажмите **Rescan** на панели.

## Needs you (стартовый экран)

Очередь **Needs you** в верхней части доски — это сквозная очередь действий по всем репозиториям: пункты отсортированы по срочности, по одному на репозиторий — только самое неотложное, а не очередной тщеславный дашборд «сколько коммитов».

- **Waiting on you**: чужие открытые PR, чужие открытые issue, красный CI на ветке по умолчанию (агрегируется в фоне через локальный, уже авторизованный `gh`, обновляется каждые 12 минут или вручную по ↻; ваши собственные открытые PR/issue считаются работой в процессе и исключаются) — клик по пункту сразу переносит на соответствующую страницу GitHub
- **At risk of being lost**: конфликты / отставание / незакоммиченное / неотправленное — чем дольше это лежит, тем выше в списке; для неотправленной работы доступен push в один клик, всё остальное открывает панель деталей
- **Overdue for release**: репозитории с привычкой тегировать релизы, у которых накопилось ≥3 коммита с последнего тега без релиза — напоминание о том, что пора выпустить релиз (репозитории, которые никогда не тегируют, не трогаются; последний тег определяется по времени создания по всему репозиторию, независимо от текущей ветки)
- **Forgotten stash**: stash, пролежавший без изменений ≥7 дней — клик сразу открывает список stash
- **Dismiss**: нажмите ✓, чтобы скрыть пункт до появления нового события — для пунктов на основе счётчика счётчик должен вырасти, для пунктов на основе изменений нужен ещё один коммит; скрытие stash — это отложить на время: он снова появится через 30 дней, чтобы по-настоящему забытый stash никогда не исчез навсегда
- Можно развернуть список сверх 10 пунктов, чтобы увидеть всё; если ничего не осталось — показывается «all clear». Сворачивается в тонкий баннер сверху

## Доска

- **Карточки**: по одной карточке на репозиторий (до 4 в ряд, одинаковой высоты). Цвет левой границы = состояние здоровья (зелёный — тихо / жёлтый — требует внимания / красный — тревога). Показывает настоящее имя · описание · язык · ветку (помечается, если не main) · разбивку рабочего дерева (`+staged ~modified`) · опережение/отставание · теги здоровья · последний коммит · ссылку на remote · теги. В подвале всегда доступны кнопки в один клик **editor / terminal / folder**
- **Строка избранного**: отдельная строка «★ favorites» вверху доски — клик открывает репозиторий в вашем редакторе
- **Кластер индикаторов**: датчики FLEET / CRIT / WARN / CLEAN в верхней панели; счётчики тревог загораются, когда > 0
- **Клик для фильтра**: клик по языку карточки или `#tag` сразу помещает его в поле поиска
- **Сортировка**: по последнему открытию / по недавней активности (по времени коммита) / по имени — избранное всегда всплывает наверх
- **Индикаторы внимания**: чипы в верхней панели, суммирующие типы проблем (нет remote / detached HEAD / неотправлено / незакоммичено / отставание / stash); клик фильтрует по ним. У «unpushed» и «behind» есть кнопка «push/pull all» в один клик
- **Группировка**: по папке / по языку / без группировки (плоский список)
- **Командная палитра ⌘/Ctrl-K**: лаунчер — введите имя, нажмите enter, чтобы открыть в редакторе (встроенные кнопки для terminal / folder / copy path / open remote)
- **Фильтр по тегам**: множественный выбор тегов в верхней панели (логическое И — карточка должна нести все выбранные теги); клик по `#tag` на карточке добавляет его. Фильтр + сортировка + группировка сохраняются вместе как именованный «view»
- **Инлайн-превью**: «⋯» на карточке показывает последние коммиты без открытия панели деталей
- **Авто-сканирование (по умолчанию выключено)**: переключатель «manual ⟳ / auto ⟳» в верхней панели. Когда включено, наблюдатель за файлами автоматически обновляет затронутые карточки (задержка 60 секунд; изменения во время задержки объединяются, а не отбрасываются). Когда выключено, состояние обновляется только по Rescan. При первом запуске доска всё равно заполняется одним сканированием
- **Плановый fetch (по умолчанию выключен)**: «fetch: off / every 5–60 min» в верхней панели — периодически выполняет fetch для каждого remote в фоне, чтобы данные об опережении/отставании оставались актуальными
- **18 языков**: переключение языка интерфейса в ⚙ Settings (упрощённый/традиционный китайский, английский, японский, корейский, испанский, французский, немецкий, португальский, русский, итальянский, арабский, хинди, бенгальский, тайский, турецкий, вьетнамский, индонезийский). При первом посещении без сохранённого предпочтения интерфейс автоматически подстраивается под язык браузера (с откатом на английский, если ничего не подошло); арабский автоматически переключает интерфейс на RTL. Относительное время локализуется нативно через `Intl`. Имена репозиториев, описания и сообщения коммитов никогда не переводятся

## Действия

- В подвале карточки всегда есть кнопки editor / terminal / folder / copy-path; открытие любой из них записывает метку времени «last opened», используемую для сортировки
- Fetch / pull (`--ff-only`) / push выполняются пакетно: выберите несколько карточек → пакетное действие из верхней панели, или кликните в один клик по индикатору внимания «unpushed» / «behind» целиком. Прогресс отображается вживую; сбой одного репозитория не останавливает остальные
- **Выполнить команду по всем репозиториям**: выберите карточки, введите команду в панели инструментов (например, `npm install`) — она выполнится параллельно в каталоге каждого выбранного репозитория. «Dry run» заранее показывает, какие репозитории будут затронуты; «view output» показывает результат по каждому репозиторию после выполнения
- **Список stash**: если где-то лежит хоть один stash, в верхней панели появляется ссылка «stash inbox (N)» — список всех отложенных изменений по всем репозиториям, с диффом по каждому пункту, `apply` / `pop` / `drop`
- Выбор нескольких карточек также позволяет массово применять теги
- **Экспорт / импорт манифеста**: экспортируйте полный манифест репозиториев (путь + remotes + группа + теги) из **+ new** для резервного копирования или переноса на другую машину; импорт заново подключает уже существующие локально репозитории и перечисляет отсутствующие для клонирования
- Команда открытия настраивается для каждой цели в поле `open` в config.json; `{path}` подставляется путём к репозиторию
- **+ New**: предлагает следующий порядковый номер (например, `028-`) и родительский каталог ваших существующих пронумерованных проектов, затем создаёт папку, выполняет `git init`, пишет README и добавляет его на доску повторным сканированием

## Проверки здоровья и статистика

- Правила (conflicted / no remote / detached HEAD / uncommitted / unpushed / untracked / behind / stash / stale) можно отключать по отдельности через `health.disabledRules`; `staleDays` задаёт порог «устаревания»
- **Сливаемые ветки**: карточки помечают, сколько локальных веток уже слиты в HEAD (исключая текущую ветку и main/master); панель деталей предлагает очистку `git branch -d` в один клик (удаляет только уже слитые ветки — безопасно)
- **GitHub (опционально, через локальный, уже авторизованный `gh`)**: очередь «needs you» агрегирует открытые PR / issue / CI на ветке по умолчанию для каждого remote на `github.com` в фоне (опрос с ограничением частоты, сохраняется на диск, мгновенно доступен после перезапуска). Панель деталей также может запросить детали открытого PR и последний запуск CI по требованию; описания репозиториев при возможности дополняются данными из GitHub
- Вкладка **Stats**: годовая тепловая карта коммитов по всем репозиториям (только локальные ветки), самые недавно активные и 10 репозиториев, которые дольше всего не трогали
- Вкладка **Worklog**: выберите диапазон дат, чтобы увидеть сквозную по репозиториям временную шкалу коммитов (с фильтром по автору — по умолчанию «только я» через автоопределение вашей git-личности), с копированием в один клик в виде еженедельного отчёта в формате Markdown
- Клик по карточке открывает панель деталей: полная разбивка здоровья, сливаемые ветки, **переключение / создание / отмена локальных веток**, **коммит на месте** (введите сообщение — и он закоммитит) с живым диффом ожидающих изменений, GitHub PR/CI, мини тепловая карта за 12 недель, последние коммиты, stash и remotes

## Организация репозиториев

- Отметьте карточку звездой ★, чтобы добавить в избранное (всплывает наверх); добавляйте/удаляйте теги в панели деталей (автодополнение по уже использованным тегам) и меняйте её группу («auto» восстанавливает группировку, выведенную из папки)
- **Заметки / задачи**: запишите «что дальше» в панели деталей — это отображается на карточке
- **Исключение**: скройте репозитории, которые не хотите видеть; исключённые репозитории по умолчанию скрыты с доски, из тревог и из командной палитры. «Excluded (N)» в верхней панели позволяет просматривать и управлять ими отдельно (снять исключение можно из панели деталей)
- Изменения применяются мгновенно и записываются в config.json без запуска пересканирования Git

## Разработка

```bash
npm run dev     # запускает сервер (7420) + vite (5173) вместе, фронтенд проксирует /api
npm test        # полный набор тестов сервера + web, плюс обе проверки типов
```

Стек: Node + Hono (весь доступ к git через `spawn`, ноль нативных зависимостей), Vite + React 19 + antd 6 (глубоко кастомизирован через CSS-переменные), chokidar + WebSocket для обновлений в реальном времени.

## Конфигурация (config.json)

| Поле | Описание |
| --- | --- |
| `roots` | Корневые каталоги для сканирования; рекурсивно находит каталоги, содержащие `.git` (глубина ≤ 6) |
| `excludes` | Имена каталогов, которые нужно пропускать (по умолчанию включает node_modules) |
| `manualRepos` | Пути репозиториев, добавленные вручную, вне настроенных `roots` |
| `tags` / `favorites` / `groupOverrides` | Переопределения тегов / избранного / группы для каждого репозитория |
| `notes` / `archived` | Заметки / флаг архивации для каждого репозитория |
| `health` | `{ staleDays, disabledRules }` |
| `open` | Шаблоны команд для целей открытия в один клик (editor / terminal / explorer) |

Переменная окружения `REPO_RADAR_CONFIG` переопределяет путь к файлу конфигурации. Сервер слушает только `127.0.0.1` и проверяет заголовок Origin как в API, так и в WebSocket.
