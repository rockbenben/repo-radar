# repo-radar

> Локальная панель, которая следит за всеми вашими Git-репозиториями и показывает, какие из них требуют вашего внимания.

Репозиториев Git у вас больше, чем можно удержать в голове. repo-radar следит за всеми и показывает те немногие, которым вы нужны сейчас, — про остальные можно забыть.

Он вытаскивает то, что вы иначе забудете проверить:

- **Незаконченная работа** — незакоммиченные, неотправленные или отложенные в stash изменения, отмеченные до того, как вы их потеряете.
- **GitHub ждёт вас** — открытые PR, issue и упавший CI, прочитанные через ваш уже авторизованный `gh`.
- **Проекты, которые остывают** — давно не тронутые или с просроченным релизом.
- **Репозитории, потерянные из виду** — все на одном экране, с поиском, открываются в один клик.

Всё, что требует действий, поднимается наверх очередью: одна запись на репозиторий, по срочности. Смахните ✓ — и она не вернётся, пока что-то действительно не изменится; исключение — отменённый stash: он всплывает через 30 дней, чтобы по-настоящему забытый не исчез навсегда.

## Поддержка

| Аспект | Windows | macOS | Linux |
| --- | --- | --- | --- |
| Установка | установщик `.exe` | `.dmg` | `.AppImage` |
| Закрытие окна | сворачивается в трей | сворачивается в трей | завершает работу — используйте **Запуск при входе**, чтобы оставить резидентным |
| Отслеживание изменений | все репозитории внутри каталога сканирования | так же | первые 200 репозиториев (порог поднимается или снимается в настройках) |

Всё работает на вашей машине и использует тот `git`, что у вас уже есть, — без аккаунта, без телеметрии, ничего не выгружается. Колонка GitHub (PR, issue, CI) необязательна и читает через [`gh` CLI](https://cli.github.com/), где вы уже вошли; без неё остальное работает.

## Установка

Возьмите файл для своей платформы в [Releases](https://github.com/rockbenben/repo-radar/releases) — Node.js не нужен. Приложение не подписано, поэтому каждая ОС предупредит при первом запуске:

- **Windows** — в окне SmartScreen *Подробнее → Выполнить в любом случае*.
- **macOS** — первый раз правый клик → Открыть. Если macOS считает файл повреждённым: `xattr -cr /Applications/repo-radar.app`.
- **Linux** — сначала `chmod +x repo-radar-*.AppImage`.

Не хотите верить бинарнику на слово? [Соберите сами](../development.md) — это `npm install && npm start`.

При первом запуске нажмите **Добавить каталоги сканирования** и укажите папку, *внутри* которой лежат репозитории, — например `~/Projects`, а не каждый репозиторий по отдельности. Он спускается на 6 уровней в поисках всего, где есть `.git`, и доска заполняется. Без JSON, без перезапуска.

## Доска

По карточке на репозиторий — цвет состояния, ветка, разбивка рабочего дерева, ahead/behind, последний коммит, теги — и **редактор / терминал / папка** в один клик.

- **Найти** — поиск либо фильтр по языку, `#tag` или индикатору. ⌘/Ctrl-K открывает лаунчер.
- **Сохранить вид** — любой фильтр + сортировка + группировка, с именем и повторным использованием.
- **Действовать пакетно** — fetch / pull / push по выбранным репозиториям или одна shell-команда во всех. Сбой одного никогда не останавливает остальные.
- **Работать на месте** — панель деталей коммитит с живым diff, переключает ветки, отменяет изменения, чистит смёрженные ветки и подтягивает PR и CI GitHub по запросу.
- **Создавать и переносить** — **+ Создать** заводит репозиторий и сразу кладёт его на доску; экспорт / импорт манифеста переносит список репозиториев — пути, remote, группы, теги — на другую машину.

Индикаторы сверху — это типы тревог: нет удалённого, отсоединённый HEAD, не отправлено, не закоммичено, отстаёт от удалённого, остался stash. Ненужные выключаются в ⚙ Настройках.

Ещё две вкладки: **Статистика** (карта коммитов за год, самые активные и самые тихие) и **Журнал работы** (скопировать период как еженедельный отчёт в Markdown).

Тёмная тема приборной панели, локализация на 18 языков, контраст текста выверен по WCAG AA в обеих темах.

## Оставаться в курсе

По умолчанию — резервное пересканирование раз в 30 минут плюс ручное из панели инструментов. Пересканирование читает только локальное состояние git — оно не обращается ни к какому remote, чтобы вычислить, что изменилось.

Автосканирование по слежению за файлами **выключено по умолчанию** и включается в настройках. Оно тоже локальное, но когда несколько проектов собираются одновременно, буфер уведомлений ядра переполняется постоянно, а переполнение — это потерянные события, которым уже нельзя верить; единственный безопасный ответ — ещё одно пересканирование, отмеренное экспоненциальным бэкоффом не чаще раза в 30 минут. Всё равно слишком высокая постоянная цена для инструмента, куда заглядывают посмотреть, что изменилось. Включите — и новые, удалённые или переименованные репозитории появляются за секунды.

Переименуйте или переместите репозиторий — теги, звезда, статус архива и заметки останутся. repo-radar узнаёт репозиторий по тому, что внутри, а не по тому, где он лежит: перемещённая папка остаётся тем же проектом, а не новым.

Плановый фоновый fetch необязателен, и это единственная функция, которая сама обращается к вашим remote. Колонка GitHub — единственное, что само выходит в сеть по таймеру: пока `gh` установлен, PR, issues и CI обновляются через него каждые 12 минут и после каждого пересканирования. Нет `gh` или нет GitHub-remote — приложение полностью локальное.

## Тихо работает в фоне

В Windows и macOS закрытие окна убирает repo-radar в трей, так что пересканирования, слежение и оповещения GitHub продолжаются; в Linux закрытие окна закрывает приложение — надёжного трея там нет. В Windows и Linux клик по значку возвращает доску; в macOS значок открывает меню, где это первый пункт — и где на всех платформах живёт Выход.

При выходе он ждёт до 10 секунд уже запущенную работу git — пакетный pull, удаление stash, — чтобы ничего не оборвалось на середине записи и не оставило устаревший `.git/index.lock`. Если этого мало, он всё равно выходит и пишет об этом в лог.

Включите **Запуск при входе** — и он стартует без окна вместе с сеансом. Уведомления рабочего стола необязательны и срабатывают только когда в списке GitHub «ждёт вас» появляется новое — PR, issue или упавший CI; при первой загрузке — никогда.

## Конфигурация

Каталоги сканирования, исключённые папки и команды открытия правятся в ⚙ Настройки → Сканирование и команды открытия. Остальное лежит в `~/.repo-radar/config.json`, который открывать почти не приходится; чисто визуальные настройки (сохранённые представления, тема, язык, журнал активности) живут в хранилище браузера. Полный список полей, файлы кэша рядом и переменные окружения для второго экземпляра описаны в [справочнике конфигурации](../configuration.md).

## Известные ограничения

- **Обновления намеренно ручные.** Автообновления нет: запустите новый установщик поверх старого.
- **Переезд, который распознающий проход сканирования пропустил, оставляет подсказку, а не молчаливую потерю.** Когда автоматическое совпадение не сработало, новая карточка предлагает *«похоже, это перемещённая копия старого пути»* — нажмите **Перенести**, и теги, звезда и заметки проследуют за репозиторием. Подсказка появляется только для репозиториев, просканированных на этой сборке хотя бы раз (в журнале должен быть их remote), и никогда — для папки назначения, которую вы ещё не добавили в каталоги сканирования.
- **В Linux нет надёжного трея**, поэтому закрытие окна завершает приложение.
- **Репозитории, добавленные по одному вне каталога сканирования, так не распознаются** — переместили такой, путь укажете сами.
- **Отмена изменений не трогает подмодули и вложенные git-репозитории** и говорит об этом, а не рапортует о полной очистке.
