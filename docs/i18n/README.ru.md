# repo-radar

> Локальная панель, которая следит за всеми вашими Git-репозиториями и показывает, какие из них требуют вашего внимания.

У вас больше Git-репозиториев, чем можно уследить вручную. repo-radar следит за всеми и показывает те немногие, что требуют вашего внимания прямо сейчас, — чтобы об остальных можно было не думать.

Он выводит на поверхность то, что вы иначе забыли бы проверить:

- **Репозитории, о которых вы забыли** — все ваши репозитории на одном экране, с поиском, любой открывается в один клик.
- **Незавершённая работа** — незакоммиченные, неотправленные или отложенные (stash) изменения, помеченные прежде, чем вы их потеряете.
- **GitHub ждёт вас** — открытые PR, issue и падающий CI по всем репозиториям, собранные через ваш локальный, уже авторизованный `gh`.
- **Проекты, которые залёживаются** — те, к которым вы давно не прикасались, или те, что пора выпускать.

Те, что требуют действия, поднимаются в верх доски в виде очереди, отсортированной по срочности, по одному пункту на репозиторий — кликните, чтобы сразу перейти к действию. Скройте пункт с помощью ✓, и он не вернётся, пока что-то действительно не изменится; когда ждать нечего, отображается «all clear». Остальные репозитории всегда в одном поиске от вас.

## Установка

Возьмите файл для своей платформы из [Releases](https://github.com/rockbenben/repo-radar/releases) — Node.js не нужен. Приложение не подписано цифровой подписью, поэтому каждая ОС предупреждает при первом запуске:

- **Windows** — запустите `repo-radar-<version>-x64-setup.exe`; в окне SmartScreen нажмите *Подробнее → Выполнить в любом случае*.
- **macOS** — откройте `repo-radar-<version>-arm64.dmg` и перетащите приложение в Applications. В первый раз кликните правой кнопкой → Открыть; если macOS называет его повреждённым, один раз снимите флаг карантина командой `xattr -cr /Applications/repo-radar.app`.
- **Linux** — `chmod +x repo-radar-<version>-x86_64.AppImage && ./repo-radar-<version>-x86_64.AppImage`.

Или запустите из исходников:

```bash
npm install
npm start
```

При первом запуске нажмите **Добавить каталоги сканирования** (или ⚙ Настройки → Каталоги сканирования) и укажите папки, где лежат ваши репозитории, — без JSON и перезапуска; пересканирование запускается в момент сохранения. Настройки лежат в `~/.repo-radar/config.json`, если предпочитаете править вручную.

## Доска

По одной карточке на репозиторий — цвет здоровья, ветка, разбивка рабочего дерева, опережение/отставание, последний коммит, теги — с кнопками в один клик **editor / terminal / folder** на каждой карточке. Отсюда вы:

- **Находите** — ищите, кликайте по языку / `#tag` / индикатору внимания для фильтрации, сортируйте и группируйте по папке или языку; сохраняйте любой фильтр + сортировку + группировку как именованный вид. ⌘/Ctrl-K открывает лаунчер.
- **Действуете пакетно** — выберите репозитории для fetch / pull (`--ff-only`) / push или выполните shell-команду параллельно по всем (с превью dry-run и выводом по каждому репозиторию). Сбой одного репозитория никогда не останавливает остальные.
- **Погружаетесь в репозиторий** — панель деталей даёт полную разбивку здоровья, переключение / создание / отмену веток, **коммит на месте** с живым диффом, GitHub PR и CI по запросу, недавние коммиты, stash, тепловую карту за 12 недель и безопасную очистку уже слитых веток в один клик.
- **Держите в актуальном состоянии** — опциональные авто-сканирование по слежению за файлами и плановый фоновый fetch, оба выключены по умолчанию. Вкладка **Stats** (годовая тепловая карта коммитов, самые/наименее активные) и вкладка **Worklog**, которая копирует диапазон дат как еженедельный отчёт в Markdown.
- **Создаёте и переносите репозитории** — **+ New** предлагает следующий пронумерованный проект, выполняет `git init`, пишет README и добавляет его на доску; экспорт / импорт манифеста переносит вашу настройку между машинами.

Интерфейс — antd 6 в тёмной теме «приборной панели пилота», локализован на 18 языков (при первом визите автоматически подстраивается под браузер, RTL для арабского).

## Работает тихо в фоне

Закрытие окна сворачивает repo-radar в трей, поэтому слежение за файлами, плановые fetch и оповещения GitHub продолжают работать — кликните по значку в трее, чтобы вернуть доску, или выйдите по-настоящему из меню трея. (На Linux, где системные треи ненадёжны, закрытие вместо этого завершает приложение; используйте Запуск при входе, чтобы оно оставалось резидентным.)

Включите **Запуск при входе** в ⚙ Настройки — и оно стартует без окна вместе с вашим сеансом, пока вы сами его не откроете. Опциональные оповещения на рабочем столе срабатывают только когда в вашу очередь попадает что-то *новое*, даже при закрытом окне. Обновления сделаны вручную намеренно (без автообновления): запустите новый установщик поверх старого. Логи попадают в `<config dir>/logs/repo-radar.log`.

## Конфигурация

Всё, к чему прикасается интерфейс, сохраняется в `~/.repo-radar/config.json` — открывать его нужно редко. Поля, которые важны:

| Поле | Что делает |
| --- | --- |
| `roots` / `excludes` / `manualRepos` | где сканировать (находит `.git` на глубину до 6), что пропускать и репозитории, добавленные вне корней |
| `health` | `{ staleDays, disabledRules }` — настройте порог «устаревания» или отключите отдельные проверки |
| `open` | шаблоны команд для кнопок editor / terminal / folder (`{path}` = путь к репозиторию) |
| `autoWatch` / `autoFetchMinutes` / `notifications` | фоновое поведение — всё выключено по умолчанию |
| `tags` / `favorites` / `groupOverrides` / `notes` / `archived` | организация по репозиториям |

`REPO_RADAR_CONFIG` и `REPO_RADAR_PORT` (по умолчанию 7420) переопределяют путь к конфигурации и порт — задайте **обе**, чтобы запустить второй, полностью независимый экземпляр. Сервер слушает только `127.0.0.1` и проверяет заголовок Origin в каждом запросе API и WebSocket.

## Разработка

```bash
npm run dev     # vite + окно приложения с горячей перезагрузкой
npm test        # тестовые наборы server + web + desktop и проверки типов
npm run dist    # сборка установщиков в dist-electron/
```

Стек: оболочка Electron + Node + Hono (весь git через `spawn`, ноль нативных зависимостей) + Vite / React 19 / antd 6, с chokidar + WebSocket для обновлений в реальном времени. Сервер Hono работает внутри основного процесса Electron, а окно загружает его через `127.0.0.1`, так что UI — это обычный HTTP + WebSocket, ровно как было бы в браузере.
