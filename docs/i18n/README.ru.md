# repo-radar

> Локальная панель, которая следит за всеми вашими Git-репозиториями и показывает, какие из них требуют вашего внимания.

У вас больше Git-репозиториев, чем можно уследить вручную. repo-radar следит за всеми и показывает те немногие, что требуют вашего внимания прямо сейчас, — чтобы об остальных можно было не думать.

Он выводит на поверхность то, что вы иначе забыли бы проверить:

- **Репозитории, о которых вы забыли** — все ваши репозитории на одном экране, с поиском, любой открывается в один клик.
- **Незавершённая работа** — незакоммиченные, неотправленные или отложенные (stash) изменения, помеченные прежде, чем вы их потеряете.
- **GitHub ждёт вас** — открытые PR, issue и падающий CI по всем репозиториям, собранные через ваш локальный, уже авторизованный `gh`.
- **Проекты, которые залёживаются** — те, к которым вы давно не прикасались, или те, что пора выпускать.

Те, что требуют действия, поднимаются в верх доски в виде очереди, отсортированной по срочности, по одному пункту на репозиторий — кликните, чтобы сразу перейти к действию. Скройте пункт с помощью ✓, и он не вернётся, пока что-то действительно не изменится; когда ждать нечего, отображается «all clear». Остальные репозитории всегда в одном поиске от вас.

## Установка

Возьмите файл для своей платформы из [Releases](https://github.com/rockbenben/repo-radar/releases) — Node.js не нужен. Приложение не подписано цифровой подписью, поэтому каждая ОС предупреждает при первом запуске:

- **Windows** — запустите `repo-radar-<version>-x64-setup.exe`; в окне SmartScreen нажмите *Подробнее → Выполнить в любом случае*.
- **macOS** — откройте `repo-radar-<version>-arm64.dmg` и перетащите приложение в Applications. В первый раз кликните правой кнопкой → Открыть; если macOS называет его повреждённым, один раз снимите флаг карантина командой `xattr -cr /Applications/repo-radar.app`.
- **Linux** — `chmod +x repo-radar-<version>-x86_64.AppImage && ./repo-radar-<version>-x86_64.AppImage`.

Или запустите из исходников:

```bash
npm install
npm start
```

При первом запуске нажмите **Добавить каталоги сканирования** (или ⚙ Настройки → Каталоги сканирования) и укажите папки, где лежат ваши репозитории, — без JSON и перезапуска; пересканирование запускается в момент сохранения. Настройки лежат в `~/.repo-radar/config.json`, если предпочитаете править вручную.

## Доска

По одной карточке на репозиторий — цвет здоровья, ветка, разбивка рабочего дерева, опережение/отставание, последний коммит, теги — с кнопками в один клик **editor / terminal / folder** на каждой карточке. Отсюда вы:

- **Находите** — ищите, кликайте по языку / `#tag` / индикатору внимания для фильтрации, сортируйте и группируйте по папке или языку; сохраняйте любой фильтр + сортировку + группировку как именованный вид. ⌘/Ctrl-K открывает лаунчер.
- **Действуете пакетно** — выберите репозитории для fetch / pull (`--ff-only`) / push или выполните shell-команду параллельно по всем (с превью dry-run и выводом по каждому репозиторию). Сбой одного репозитория никогда не останавливает остальные.
- **Погружаетесь в репозиторий** — панель деталей даёт полную разбивку здоровья, переключение / создание / отмену веток, **коммит на месте** с живым диффом, GitHub PR и CI по запросу, недавние коммиты, stash, тепловую карту за 12 недель и очистку уже слитых веток в один клик — она предлагается только пока вы на `main`/`master`: это единственная позиция, где «уже слита» означает «слита в основную ветку». Отмена изменений возвращает отслеживаемые файлы и удаляет неотслеживаемые, но не трогает содержимое сабмодулей и неотслеживаемые вложенные git-репозитории; если что-то осталось, она скажет об этом, а не отчитается об успехе.
- **Держите в актуальном состоянии** — путь обновления по умолчанию — полный скан раз в 30 минут плюс ручной скан из панели. Авто-сканирование по слежению за файлами **по умолчанию выключено** и включается вручную в настройках: оно чисто локальное и не ходит в сеть, но когда несколько проектов собираются одновременно, буфер уведомлений ядра переполняется постоянно, и каждое переполнение стоит одного скана — слишком высокая постоянная плата для инструмента, которым смотрят, что изменилось. Если включить, на Windows и macOS одно рекурсивное слежение на каждый каталог сканирования покрывает все репозитории внутри него, поэтому добавление, удаление или переименование репозитория видно через считанные секунды; на Linux репозитории отслеживаются по отдельности, а `watchLimit` (по умолчанию 200, 0 = без лимита) ограничивает их число, отдавая приоритет избранным и недавно закоммиченным. При непрерывных переполнениях догоняющие сканы расходятся экспоненциально (не чаще раза в 30 минут) и больше не пересоздают слежение — это происходит только когда цель слежения действительно исчезла. Полный скан раз в 30 минут подхватывает пропущенное слежением, в панели показано «последний скан», а панель настроек показывает охват в реальном времени («отслеживается M из N»). Переименование или перемещение репозитория сохраняет его теги, звезду, состояние архива и заметки — repo-radar отслеживает идентичность, а не только путь. Сопоставление происходит на круге сканирования **сразу после** перемещения, из-за чего остаются два зазора: медленное перемещение между томами, растянутое на два круга сканирования, когда между ними попадает добавление/удаление другого репозитория или периодический полный скан; и перемещение, чья новая папка на этом круге не сканируется — вынести репозиторий из каталогов сканирования, а его новое место добавить как каталог сканирования только позже, самый обычный способ попасть в него. Оба откатываются к идентичности по пути: репозиторий возвращается новой карточкой, а его теги/звезда/архив/заметки остаются под id, которого у него больше нет. Плановый фоновый fetch включается по желанию. Вкладка **Stats** (годовая тепловая карта коммитов, самые/наименее активные) и вкладка **Worklog**, которая копирует диапазон дат как еженедельный отчёт в Markdown.
- **Создаёте и переносите репозитории** — **+ New** предлагает следующий пронумерованный проект, выполняет `git init`, пишет README и добавляет его на доску; экспорт / импорт манифеста переносит вашу настройку между машинами.

Интерфейс — antd 6 в тёмной теме «приборной панели пилота», локализован на 18 языков (при первом визите автоматически подстраивается под браузер, RTL для арабского).

## Работает тихо в фоне

Закрытие окна сворачивает repo-radar в трей, поэтому периодический скан, слежение за файлами (если вы его включили), плановые fetch и оповещения GitHub продолжают работать — кликните по значку в трее, чтобы вернуть доску, или выйдите по-настоящему из меню трея. (На Linux, где системные треи ненадёжны, закрытие вместо этого завершает приложение; используйте Запуск при входе, чтобы оно оставалось резидентным.)

При выходе repo-radar ждёт до 10 секунд завершения уже начатой работы git — пакетного pull, отброшенного stash, планового fetch — чтобы ничего не оборвалось на середине записи и не оставило устаревший `.git/index.lock`. Если этого времени не хватит, приложение всё равно выйдет и напишет об этом в журнал: это единственное место, объясняющее `index.lock`, который вы найдёте позже.

Включите **Запуск при входе** в ⚙ Настройки — и оно стартует без окна вместе с вашим сеансом, пока вы сами его не откроете. Опциональные оповещения на рабочем столе срабатывают только когда в вашу очередь попадает что-то *новое*, даже при закрытом окне. Обновления сделаны вручную намеренно (без автообновления): запустите новый установщик поверх старого. Логи попадают в `<config dir>/logs/repo-radar.log`.

## Конфигурация

Всё, к чему прикасается интерфейс, сохраняется в `~/.repo-radar/config.json` — открывать его нужно редко. Поля, которые важны:

| Поле | Что делает |
| --- | --- |
| `roots` / `excludes` / `manualRepos` | где сканировать (находит `.git` на глубину до 6, по символическим ссылкам не идёт), что пропускать и репозитории, добавленные вне корней — запись `manualRepos`, которую переименовали или переместили, не отслеживается по идентичности, как отсканированный репозиторий; карточка остаётся с ошибкой, пока вы не обновите её путь здесь, а если перемещение случилось больше одного круга сканирования назад, это обновление вернёт карточку, но не её теги/звезду/архив/заметки |
| `health` | `{ staleDays, disabledRules }` — настройте порог «устаревания» или отключите отдельные проверки |
| `open` | шаблоны команд для кнопок editor / terminal / folder (`{path}` = путь к репозиторию) |
| `autoWatch` / `autoScanMinutes` / `watchLimit` / `autoFetchMinutes` / `notifications` | фоновое поведение — по умолчанию включён только `autoScanMinutes` (30); остальные три, включая `autoWatch`, выключены. `watchLimit` (200, 0 = без лимита) действует **только на Linux**, где репозитории отслеживаются по отдельности; Windows и macOS используют одно рекурсивное слежение на каталог сканирования и всегда покрывают все репозитории |
| `tags` / `favorites` / `groupOverrides` / `notes` / `archived` | организация по репозиториям |

Рядом с `config.json` лежат ещё два файла, оба можно безопасно удалить — repo-radar их пересоберёт, но цена разная. `repo-cache.json` помнит «тяжёлые» git-поля каждого репозитория (stash, теги, remote, слитые ветки…), привязанные к отпечатку `.git`, поэтому неизменившийся репозиторий пропускает эти вызовы git на следующем скане; удалите его — следующий скан просто один раз пройдёт медленнее. `repo-identity.json` — это журнал идентичности, благодаря которому переименованный или перемещённый репозиторий сохраняет свои теги, звезду, состояние архива и заметки вместо того, чтобы считаться совершенно новым. Здесь потеря немедленная, а не отложенная: любой репозиторий, уже переименованный или перемещённый **до** потери файла, получит совершенно новый id на самом следующем скане, а его теги/звезда/архив/заметки останутся под тем id, которого у него больше нет. Репозитории, которые никогда не переименовывали, не затронуты, и с момента пересборки журнала переименования снова под защитой.

`REPO_RADAR_CONFIG` и `REPO_RADAR_PORT` (по умолчанию 17420) переопределяют путь к конфигурации и порт — задайте **обе**, чтобы запустить второй, полностью независимый экземпляр. Сервер слушает только `127.0.0.1` и проверяет заголовок Origin в каждом запросе API и WebSocket.

Порт по умолчанию намеренно выбран выше диапазона динамических портов ОС: Windows по умолчанию использует 49152–65535, но после установки Hyper-V/WSL2 — 1024–15000, и система резервирует из активного диапазона целые блоки. Порт внутри такого блока не привязывается с ошибкой `EACCES`, а сами блоки сдвигаются после перезагрузок.

Если **порт по умолчанию** всё равно не удаётся занять, repo-radar не отказывается запускаться, а переходит к следующему кандидату (`+1000`, `+2000`, `+3000`, затем порт, выданный системой), запоминает выбранный порт и использует его при следующих запусках, а также показывает его рядом с версией в ⚙ Настройках. Запоминание важно потому, что порт входит в origin страницы, а доска хранит сохранённые виды, журнал активности, тему и язык в привязанном к origin хранилище браузера: если позволить порту скакать, эти данные будут то пропадать, то возвращаться. Чтобы вернуться к порту по умолчанию, удалите `<каталог конфигурации>/port-state.json`.

Порт, заданный вами через `REPO_RADAR_PORT`, никогда не подменяется — это обязательство перед закладками, апстримами обратного прокси и скриптами, поэтому неудачная привязка приводит к явной ошибке. То же самое в `npm run dev`, где цель прокси vite фиксируется при загрузке конфигурации.

## Разработка

```bash
npm run dev     # vite + окно приложения с горячей перезагрузкой
npm test        # тестовые наборы server + web + desktop и проверки типов
npm run dist    # сборка установщиков в dist-electron/
```

Стек: оболочка Electron + Node + Hono (весь git через `spawn`, ноль нативных зависимостей) + Vite / React 19 / antd 6, с chokidar + WebSocket для обновлений в реальном времени. Сервер Hono работает внутри основного процесса Electron, а окно загружает его через `127.0.0.1`, так что UI — это обычный HTTP + WebSocket, ровно как было бы в браузере.
