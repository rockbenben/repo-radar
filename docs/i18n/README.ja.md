# repo-radar

> 365オープンソース計画 #027 · ローカルGitリポジトリダッシュボード——リポジトリ横断のアクションキューで、今まさに対応が必要なものに答えます。

マシン上のすべてのリポジトリをスキャンし、最初に見せるべき1画面を提示するローカルGitリポジトリダッシュボードです。それはリポジトリ横断の**アクションキュー**——*今まさに自分の対応が必要なもの*に答える画面です。項目をクリックすればそのまま対応できます。UIはantd 6をベースに、計器盤（インストゥルメント・コックピット）風の深みのあるテーマで構築されています。

## クイックスタート

```bash
npm install
npm run build   # build the frontend
npm start       # http://localhost:7420
```

初回起動時に `~/.repo-radar/config.json` にデフォルト設定が作成されます。`roots` を編集してスキャン対象のディレクトリを追加し（例：`D:\Projects` — JSON内ではバックスラッシュを `D:\\Projects` のようにエスケープします）、パネルの**Rescan**をクリックしてください。

## Needs you（エントリー画面）

ボード上部の**Needs you**キューは、リポジトリ横断のアクションキューです。緊急度でランク付けされ、1リポジトリにつき1項目——「コミット数がいくつ」といった見栄えだけのダッシュボードではなく、最も緊急な1件だけを示します。

- **Waiting on you**：他者が開いたPR、他者が開いたIssue、デフォルトブランチの赤いCI（ローカルで既に認証済みの `gh` を使ってバックグラウンドで集約、12分ごとに自動更新、または ↻ で手動更新。自分自身が開いたPR/Issueは「作業中」として扱われ除外されます）——項目をクリックすると対応するGitHubページに直接ジャンプします
- **At risk of being lost**：コンフリクト／遅れ（behind）／未コミット／未プッシュ。放置期間が長いほど上位にランクされます——未プッシュの作業はワンクリックでプッシュでき、それ以外は詳細パネルが開きます
- **Overdue for release**：タグ付けの習慣があるのに最新タグ以降コミットが3件以上たまっていて、まだリリースされていないリポジトリ——リリースを促す通知です（タグ付けを一切しないリポジトリは対象外です。最新タグは現在のブランチに関係なく、リポジトリ全体の作成時刻で判定されます）
- **Forgotten stash**：7日以上放置されているスタッシュ——クリックするとスタッシュ受信箱に直接移動します
- **Dismiss**：✓をタップすると、次に何か変化が起きるまでその項目を消せます——件数ベースの項目は件数が増える必要があり、変更ベースの項目はさらにコミットが必要です。スタッシュの解除はスヌーズ扱いで、30日後に再表示されるため、本当に忘れられたスタッシュが永遠に隠れたままになることはありません
- 10件を超える項目は展開してすべて表示できます。何も残っていない場合は「all clear」と表示されます。上部では薄いバナーに折りたたまれます

## ボード

- **カード**：リポジトリごとに1枚（1行あたり最大4枚、高さは均一）。左端の色 = ヘルス状態（緑 = 静穏 / アンバー = 要注意 / 赤 = 警告）。実際の名前・説明・言語・ブランチ（mainでない場合はフラグ表示）・作業ツリーの内訳（`+staged ~modified`）・ahead/behind・ヘルスタグ・最終コミット・リモートリンク・タグを表示します。フッターには常にワンクリックの**エディタ／ターミナル／フォルダ**ボタンがあります
- **お気に入り行**：ボード上部にある専用の「★ favorites」行——クリックするとエディタで開きます
- **Readoutクラスタ**：上部バーのFLEET / CRIT / WARN / CLEANゲージ。アラート件数が0より大きいと点灯します
- **クリックで絞り込み**：カードの言語や`#tag`をクリックすると、そのまま検索ボックスに反映されます
- **並び替え**：最後に開いた順 / 最近のアクティビティ順（コミット時刻順） / 名前順——お気に入りは常に上部に固定されます
- **Attentionランプ**：問題の種類（リモートなし／detached HEAD／未プッシュ／未コミット／behind／stash）を要約する上部バーのチップ。クリックすると絞り込めます。「Unpushed」と「behind」にはそれぞれワンクリックの「すべてpush/pull」機能があります
- **グルーピング**：フォルダ別 / 言語別 / グループなし（フラット）
- **コマンドパレット ⌘/Ctrl-K**：ランチャー——名前を入力してEnterを押すとエディタで開きます（ターミナル／フォルダ／パスコピー／リモートを開く、のインラインボタン付き）
- **タグフィルタ**：上部バーでのタグのマルチセレクト（AND条件——選択したすべてのタグを持つ必要があります）。カードの`#tag`をクリックすると追加されます。フィルタ＋並び替え＋グルーピングは名前付きの「view」としてまとめて保存されます
- **インラインプレビュー**：カード上の「⋯」をクリックすると、詳細パネルを開かずに最近のコミットがポップアップ表示されます
- **自動スキャン（デフォルトはオフ）**：上部バーの「manual ⟳ / auto ⟳」トグル。オンにするとファイルウォッチャーが影響を受けたカードを自動更新します（クールダウンは60秒。クールダウン中の変更はマージされ、失われることはありません）。オフの場合はRescan時のみ状態が更新されます。初回起動時は1回のスキャンでボードが構築されます
- **定期フェッチ（デフォルトはオフ）**：上部バーの「fetch: off / every 5–60 min」——バックグラウンドですべてのリモートを定期的にフェッチし、ahead/behindを最新の状態に保ちます
- **18言語対応**：⚙設定からUI言語を切り替えられます（簡体字中国語／繁体字中国語、英語、日本語、韓国語、スペイン語、フランス語、ドイツ語、ポルトガル語、ロシア語、イタリア語、アラビア語、ヒンディー語、ベンガル語、タイ語、トルコ語、ベトナム語、インドネシア語）。保存済みの設定がない初回訪問時は、ブラウザの言語に自動的に一致します（一致しない場合は英語にフォールバック）。アラビア語では自動的にRTLに切り替わります。相対時刻は`Intl`によってネイティブにローカライズされます。リポジトリ名、説明、コミットメッセージは常に翻訳されません

## アクション

- カードのフッターには常にエディタ／ターミナル／フォルダ／パスコピーのボタンが表示されます。いずれかを開くと、並び替えに使われる「最後に開いた」タイムスタンプが記録されます
- Fetch / pull（`--ff-only`）/ pushはバッチとして実行できます：複数のカードを選択→上部バーからバッチアクション、または「unpushed」／「behind」のAttentionランプをワンクリック。進捗はリアルタイムに表示され、1つのリポジトリが失敗しても他は止まりません
- **複数リポジトリにまたがるコマンド実行**：カードを選択し、ツールバーにコマンドを入力すると（例：`npm install`）、選択したすべてのリポジトリのディレクトリ内で並列に実行されます。「Dry run」で先にどのリポジトリが対象になるかをプレビューでき、「view output」でリポジトリごとの結果を後から確認できます
- **スタッシュ受信箱**：スタッシュが1つでもあると、上部バーに「stash inbox (N)」リンクが表示されます——すべてのリポジトリのスタッシュされた変更を一覧表示し、項目ごとの差分と`apply` / `pop` / `drop`が行えます
- 複数カードを選択すると、タグの一括適用もできます
- **マニフェストのエクスポート／インポート**：**+ new**からリポジトリマニフェスト全体（パス＋リモート＋グループ＋タグ）をエクスポートし、バックアップやマシン移行に利用できます。インポート時はローカルに既に存在するリポジトリを再認識し、存在しないものはクローン用に一覧表示します
- 開くコマンドはconfig.jsonの`open`でターゲットごとに設定可能です。`{path}`はリポジトリのパスに置き換えられます
- **+ New**：次の連番（例：`028-`）と、既存の連番付きプロジェクトの親ディレクトリを提案したうえで、フォルダを作成し、`git init`を実行し、READMEを書き込み、ボードに再スキャンして反映します

## ヘルスチェックと統計

- ルール（conflicted / no remote / detached HEAD / uncommitted / unpushed / untracked / behind / stash / stale）は`health.disabledRules`で個別に無効化できます。`staleDays`で「stale」の判定しきい値を設定します
- **マージ可能なブランチ**：カードには、HEADに既にマージ済みのローカルブランチの数がフラグ表示されます（現在のブランチとmain/masterを除く）。詳細パネルではワンクリックの`git branch -d`クリーンアップが提供されます（マージ済みのブランチのみを削除するため安全です）
- **GitHub（任意、ローカルで既に認証済みの`gh`を利用）**：「needs you」キューは、`github.com`リモートを持つすべてのリポジトリについて、開いているPR／Issue／デフォルトブランチのCIをバックグラウンドで集約します（レート制限付きポーリング、ディスクへ永続化、再起動時も即座に表示）。詳細パネルからも、開いているPRの詳細や最新のCI実行状況をオンデマンドで問い合わせできます。リポジトリの説明は、可能な場合GitHubから補完されます
- **Stats**タブ：年間のリポジトリ横断コミットヒートマップ（ローカルブランチのみ）、最も最近アクティブなリポジトリ、最も長く手つかずのリポジトリ10件
- **Worklog**タブ：期間を指定してリポジトリ横断のコミットタイムラインを表示（作者でフィルタ可能——デフォルトはgitの識別情報を自動検出した「自分のみ」）。Markdown形式の週次レポートとしてワンクリックでコピーできます
- カードをクリックすると詳細パネルが開きます：完全なヘルス内訳、マージ可能なブランチ、**ローカルブランチの切り替え／作成／破棄**、**その場でコミット**（メッセージを入力するとコミットされます）と保留中の変更のライブ差分、GitHubのPR/CI、12週間のミニヒートマップ、最近のコミット、スタッシュ、リモート

## リポジトリの整理

- カードに★を付けてお気に入り登録できます（上部に固定表示）。詳細パネルでタグの追加／削除ができ（使用済みのタグからオートコンプリート）、グループも変更できます（「auto」でフォルダ由来のグルーピングに戻せます）
- **メモ／To-Do**：詳細パネルに「次にやること」を書き留められます——カードにも表示されます
- **除外**：見たくないリポジトリを非表示にできます。除外されたリポジトリはデフォルトでボード、アラート、コマンドパレットから隠されます。上部バーの「Excluded (N)」から別途表示／管理できます（詳細パネルから除外を解除）
- 変更は即座に反映され、config.jsonに書き込まれます。Gitの再スキャンはトリガーされません

## 開発

```bash
npm run dev     # runs server(7420) + vite(5173) together, frontend proxies /api
npm test        # full server + web test suite + both typechecks
```

スタック：Node + Hono（すべてのGitアクセスは`spawn`経由、ネイティブ依存ゼロ）、Vite + React 19 + antd 6（CSS変数で深くカスタマイズ）、chokidar + WebSocketによるライブ更新。

## 設定（config.json）

| フィールド | 説明 |
| --- | --- |
| `roots` | スキャン対象のルートディレクトリ。`.git`を含むディレクトリを再帰的に検出します（深さ ≤ 6） |
| `excludes` | スキップするディレクトリ名（デフォルトにはnode_modulesが含まれます） |
| `manualRepos` | 設定済みのroots以外で、手動で追加されたリポジトリのパス |
| `tags` / `favorites` / `groupOverrides` | リポジトリID単位のタグ／お気に入り／グループの上書き設定 |
| `notes` / `archived` | リポジトリID単位のメモ／アーカイブフラグ |
| `health` | `{ staleDays, disabledRules }` |
| `open` | ワンクリックで開く対象（エディタ／ターミナル／エクスプローラー）のコマンドテンプレート |

`REPO_RADAR_CONFIG` 環境変数で設定ファイルのパスを上書きできます。サーバーは`127.0.0.1`でのみリッスンし、APIとWebSocketの両方でOriginヘッダーを検証します。
