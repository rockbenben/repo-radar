# repo-radar

> ৩৬৫ ওপেন সোর্স প্ল্যান #027 · একটি লোকাল ড্যাশবোর্ড যা আপনার সব Git রিপো নজরে রাখে এবং দেখায় কোনগুলোতে আপনার দরকার।

নিজে হাতে হিসেব রাখা যায় তার চেয়ে বেশি Git রিপো আপনার আছে। repo-radar সেগুলোর সবকটির উপর নজর রাখে এবং এই মুহূর্তে যেগুলোতে আপনার দরকার সেই অল্প কয়েকটিই সামনে আনে — যাতে বাকিগুলো নিয়ে আর মাথা ঘামাতে না হয়।

যা আপনি চেক করতে ভুলে যেতেন, তা এটি সামনে এনে দেয়:

- **যেসব রিপোর খেই হারিয়ে ফেলেছেন** — আপনার মালিকানার প্রতিটি রিপো এক স্ক্রিনে, সার্চ করা যায়, যেকোনোটি এক ক্লিকেই খুলে ফেলুন।
- **অসমাপ্ত কাজ** — আনকমিটেড, আনপুশড, বা স্ট্যাশ করা পরিবর্তন, হারিয়ে ফেলার আগেই চিহ্নিত।
- **GitHub আপনার অপেক্ষায়** — প্রতিটি রিপো জুড়ে খোলা PR, ইস্যু ও ব্যর্থ CI, আপনার লোকাল, আগে থেকেই authenticated `gh` দিয়ে এক জায়গায় জড়ো করা।
- **বাসি হয়ে যাওয়া প্রজেক্ট** — যেগুলো অনেক দিন ধরে ছোঁয়া হয়নি, বা যেগুলো কবেই শিপ হয়ে যাওয়ার কথা ছিল।

যেগুলোতে ব্যবস্থা নেওয়া দরকার সেগুলো একটা কিউ হয়ে বোর্ডের একদম উপরে উঠে আসে — কতটা জরুরি সেই অনুযায়ী সাজানো, প্রতি রিপোতে একটি করে আইটেম — সরাসরি ব্যবস্থা নিতে ক্লিক করুন। ✓ দিয়ে dismiss করলে সত্যি কিছু না বদলানো পর্যন্ত সেটা সরে থাকে; কিছু বাকি না থাকলে "all clear" লেখা ফুটে ওঠে। আর বাকি রিপোগুলো তো সবসময় স্রেফ একটা সার্চ দূরেই।

## ইনস্টল

[Releases](https://github.com/rockbenben/repo-radar/releases) থেকে আপনার প্ল্যাটফর্মের ফাইলটি নিন — Node.js লাগবে না। অ্যাপটি কোড-সাইন করা নয়, তাই প্রতিটি OS প্রথমবার চালালে সতর্ক করে:

- **Windows** — `repo-radar-<version>-x64-setup.exe` চালান; SmartScreen প্রম্পটে *More info → Run anyway* ক্লিক করুন।
- **macOS** — `repo-radar-<version>-arm64.dmg` খুলে অ্যাপটি Applications-এ টেনে নিন। প্রথমবার রাইট-ক্লিক → Open করুন; macOS যদি এটিকে damaged বলে, তাহলে `xattr -cr /Applications/repo-radar.app` দিয়ে quarantine ফ্ল্যাগটি একবার পরিষ্কার করুন।
- **Linux** — `chmod +x repo-radar-<version>-x86_64.AppImage && ./repo-radar-<version>-x86_64.AppImage`।

অথবা সোর্স থেকে চালান:

```bash
npm install
npm start
```

প্রথমবার চালু করলে, **Add scan directories** (বা ⚙ Settings → Scan directories) ক্লিক করুন এবং কোন ফোল্ডারগুলোতে আপনার রিপো রাখা আছে তা দেখিয়ে দিন — JSON নেই, রিস্টার্ট নেই; সেভ করার মুহূর্তেই এটি আবার স্ক্যান করে নেয়। নিজে হাতে এডিট করতে চাইলে সেটিংস `~/.repo-radar/config.json`-এ থাকে।

## বোর্ড

প্রতি রিপোতে একটি করে কার্ড — স্বাস্থ্যের রং, ব্রাঞ্চ, ওয়ার্কিং-ট্রি ব্রেকডাউন, ahead/behind, সর্বশেষ কমিট, ট্যাগ — প্রতিটি কার্ডে এক-ক্লিক **editor / terminal / folder** সহ। এখান থেকে আপনি:

- **Find** — সার্চ করুন, একটি ভাষা / `#tag` / attention-lamp-এ ক্লিক করে ফিল্টার, সর্ট, এবং ফোল্ডার বা ভাষা অনুসারে গ্রুপ করুন; যেকোনো ফিল্টার + সর্ট + গ্রুপ একটি নামযুক্ত view হিসেবে সেভ করুন। ⌘/Ctrl-K একটি লঞ্চার খোলে।
- **Act in batches** — fetch / pull (`--ff-only`) / push করার জন্য রিপো নির্বাচন করুন, অথবা সেগুলোর ওপর সমান্তরালে একটি শেল কমান্ড চালান (dry-run প্রিভিউ ও প্রতি-রিপো আউটপুট সহ)। একটি রিপো ব্যর্থ হলেও বাকিগুলো কখনো থেমে যায় না।
- **Dig into a repo** — ডিটেইল প্যানেল একটি সম্পূর্ণ স্বাস্থ্য বিবরণ দেয়, ব্রাঞ্চ switch / create / discard, লাইভ diff সহ **commit in place**, চাহিদামতো GitHub PR ও CI, সাম্প্রতিক কমিট, স্ট্যাশ, একটি ১২-সপ্তাহের হিটম্যাপ, এবং ইতিমধ্যে মার্জ হয়ে যাওয়া ব্রাঞ্চের এক-ক্লিক ক্লিনআপ — এটি কেবল তখনই দেখানো হয় যখন আপনি `main`/`master`-এ আছেন, কারণ একমাত্র সেখানেই «ইতিমধ্যে মার্জ» মানে «ট্রাঙ্কে মার্জ»। পরিবর্তন discard করলে ট্র্যাক করা ফাইল আগের অবস্থায় ফিরে যায় ও আনট্র্যাক ফাইল মুছে যায়, কিন্তু submodule-এর ভিতরের বিষয়বস্তু আর আনট্র্যাক নেস্টেড git রিপো অস্পৃশ্য থাকে; কিছু বাকি থেকে গেলে এটি সফল বলে রিপোর্ট না করে সেটাই জানিয়ে দেয়।
- **Stay fresh** — ডিফল্ট রিফ্রেশের পথ হলো প্রতি ৩০ মিনিটের ফলব্যাক স্ক্যান আর উপরের বার থেকে হাতে করা স্ক্যান। ফাইল-ওয়াচ অটো-স্ক্যান **ডিফল্টে বন্ধ**, দরকার হলে সেটিংস প্যানেল থেকে নিজে চালু করে নিতে হয়: এটি শুধু লোকাল, নেটওয়ার্কে কখনো যায় না, কিন্তু একসাথে কয়েকটি প্রজেক্ট বিল্ড হতে থাকলে কার্নেলের নোটিফিকেশন বাফার অনবরত উপচে পড়ে, আর প্রতিবার উপচে পড়ার দাম একটি স্ক্যান — «কী বদলেছে একবার দেখে নিই» ধরনের টুলের জন্য এই স্থায়ী খরচ বড় বেশি। চালু করলে, Windows ও macOS-এ প্রতি স্ক্যান ডিরেক্টরির জন্য একটিমাত্র রিকার্সিভ ওয়াচ তার নিচের সব রিপো ঢেকে দেয়, ফলে কোনো রিপো যোগ করা, মুছে ফেলা বা নাম বদলানো কয়েক সেকেন্ডেই ধরা পড়ে; Linux-এ রিপো আলাদা আলাদা ওয়াচ হয় এবং `watchLimit` (ডিফল্ট ২০০, ০ = সীমাহীন) কতগুলো ওয়াচ হবে তা সীমিত করে, পছন্দের ও সদ্য কমিট হওয়া রিপো অগ্রাধিকার পায়। উপচে পড়া চলতে থাকলে পুষিয়ে দেওয়া স্ক্যানগুলোর ব্যবধান সূচকীয় হারে বাড়ে (বড়জোর ৩০ মিনিটে একবার) এবং ওয়াচ হ্যান্ডেল আর নতুন করে বানানো হয় না — সেটি কেবল তখনই হয় যখন ওয়াচের লক্ষ্য সত্যিই হারিয়ে যায়। প্রতি ৩০ মিনিটের পূর্ণ স্ক্যান ওয়াচের হাতছাড়া হওয়াটা তুলে নেয়, উপরের বারে «শেষ স্ক্যান» দেখা যায়, আর সেটিংস প্যানেলে কভারেজ সরাসরি দেখা যায় («N-এর মধ্যে M ওয়াচ»)। কোনো রিপোর নাম বদলালে বা সরিয়ে নিলে তার ট্যাগ, স্টার, আর্কাইভ অবস্থা ও নোট থেকে যায় — repo-radar কেবল পাথ নয়, পরিচয় অনুসরণ করে। মিলটা হয় সরানোর **ঠিক পরের** স্ক্যান রাউন্ডে, ফলে দুটো ফাঁক থাকে: এক, ভলিউম পেরিয়ে ধীরে সরানো যা দুটো স্ক্যান রাউন্ডে ছড়িয়ে পড়ে এবং মাঝখানে অন্য কোনো রিপো যোগ/বাদ পড়া কিংবা নিয়মিত পূর্ণ স্ক্যান এসে পড়ে; দুই, এমন সরানো যার গন্তব্য সেই রাউন্ডে স্ক্যানই হয় না — রিপোকে স্ক্যান ডিরেক্টরির বাইরে সরিয়ে পরে তার নতুন জায়গাটিকে স্ক্যান ডিরেক্টরি হিসেবে যোগ করা এতে পড়ার সবচেয়ে সাধারণ পথ। দুটোই পাথ-ভিত্তিক পরিচয়ে ফিরে যায়: রিপো একেবারে নতুন কার্ড হয়ে ফেরে, আর তার ট্যাগ/স্টার/আর্কাইভ/নোট পড়ে থাকে সেই id-র নিচে যা আর তার নয়। নির্ধারিত ব্যাকগ্রাউন্ড fetch নিজে চালু করে নিতে হয়। একটি **Stats** ট্যাব (এক বছরের কমিট হিটম্যাপ, সর্বাধিক/সর্বনিম্ন সক্রিয়) এবং একটি **Worklog** ট্যাব যা কোনো একটা তারিখ-পরিসরকে Markdown সাপ্তাহিক রিপোর্ট হিসেবে কপি করে দেয়।
- **Start & move repos** — **+ New** পরবর্তী নম্বরযুক্ত প্রজেক্ট প্রস্তাব করে, `git init` চালায়, একটি README লেখে, এবং সেটিকে বোর্ডে তুলে নেয়; manifest export / import আপনার সেটআপ এক মেশিন থেকে আরেক মেশিনে বয়ে নিয়ে যায়।

UI হলো antd 6, একটি ডার্ক ইনস্ট্রুমেন্ট-ককপিট থিমে, ১৮টি ভাষায় স্থানীয়কৃত (প্রথম ভিজিটে আপনার ব্রাউজারের সাথে স্বয়ংক্রিয়ভাবে মিলে যায়, আরবির জন্য RTL)।

## ব্যাকগ্রাউন্ডে নীরবে চলে

উইন্ডো বন্ধ করলে repo-radar ট্রেতে নেমে যায়, ফলে ফলব্যাক স্ক্যান, ফাইল-ওয়াচিং (যদি চালু করে থাকেন), নির্ধারিত fetch ও GitHub অ্যালার্ট চলতে থাকে — বোর্ড ফিরিয়ে আনতে ট্রে আইকনে ক্লিক করুন, বা ট্রে মেনু থেকে সত্যিকারভাবে quit করুন। (Linux-এ, যেখানে ডেস্কটপ ট্রে নির্ভরযোগ্য নয়, বন্ধ করলে বরং quit হয়ে যায়; একে চালু রাখতে Launch at login ব্যবহার করুন।)

quit করার সময় repo-radar ইতিমধ্যে চলতে থাকা git কাজ — ব্যাচ pull, discard করা stash, নির্ধারিত fetch — শেষ হওয়ার জন্য সর্বোচ্চ ১০ সেকেন্ড অপেক্ষা করে, যাতে লেখার মাঝপথে কিছু কাটা না পড়ে আর পিছনে পুরনো `.git/index.lock` না থেকে যায়। ওই সময় যথেষ্ট না হলে এটি তবুও বেরিয়ে যায় এবং সেটা লগে লিখে রাখে: পরে পাওয়া কোনো `index.lock`-এর কারণ ব্যাখ্যা করার একমাত্র জায়গা ওইটুকুই।

⚙ Settings-এ **Launch at login** অন করুন এবং এটি আপনার সেশনের সাথে হেডলেসভাবে চালু হয় — যতক্ষণ না চান ততক্ষণ কোনো উইন্ডো নেই। ঐচ্ছিক ডেস্কটপ নোটিফিকেশন কেবল তখনই আসে যখন *নতুন* কিছু আপনার কিউতে পৌঁছায়, উইন্ডো বন্ধ থাকলেও। আপগ্রেড ইচ্ছাকৃতভাবেই ম্যানুয়াল (কোনো অটো-আপডেট নেই): নতুন ইনস্টলার পুরনোটির ওপর চালান। লগ `<config dir>/logs/repo-radar.log`-এ জমা হয়।

## কনফিগারেশন

UI যা কিছু স্পর্শ করে তার সবই `~/.repo-radar/config.json`-এ সেভ হয় — এটি খোলার দরকার খুব কমই পড়ে। যে ফিল্ডগুলো গুরুত্বপূর্ণ:

| ফিল্ড | কী করে |
| --- | --- |
| `roots` / `excludes` / `manualRepos` | কোথায় স্ক্যান করবে (`.git` ৬ গভীরতা পর্যন্ত খোঁজে, symlink ধরে এগোয় না), কী বাদ দেবে, এবং roots-এর বাইরে যোগ করা রিপো — `manualRepos`-এর যে এন্ট্রির নাম বদলে যায় বা যেটি সরে যায়, সেটি স্ক্যান করা রিপোর মতো পরিচয় ধরে অনুসরণ করা হয় না; আপনি এখানে তার পাথ হালনাগাদ না করা পর্যন্ত কার্ডটি এরর অবস্থায় থাকে, আর সরানোটা এক স্ক্যান রাউন্ডের চেয়েও আগে হয়ে থাকলে সেই হালনাগাদ কার্ড ফিরিয়ে আনে, তার ট্যাগ/স্টার/আর্কাইভ/নোট ফিরিয়ে আনে না |
| `health` | `{ staleDays, disabledRules }` — "stale" থ্রেশহোল্ড টিউন করুন বা আলাদা আলাদা চেক নিষ্ক্রিয় করুন |
| `open` | editor / terminal / folder বাটনের কমান্ড টেমপ্লেট (`{path}` = রিপো পাথ) |
| `autoWatch` / `autoScanMinutes` / `watchLimit` / `autoFetchMinutes` / `notifications` | ব্যাকগ্রাউন্ড আচরণ — ডিফল্টে চালু কেবল `autoScanMinutes` (৩০); `autoWatch` সহ বাকি তিনটি বন্ধ। `watchLimit` (২০০, ০ = সীমাহীন) **কেবল Linux-এ** প্রযোজ্য, যেখানে রিপো আলাদা আলাদা ওয়াচ হয়; Windows ও macOS প্রতি স্ক্যান ডিরেক্টরির জন্য একটি রিকার্সিভ ওয়াচ ব্যবহার করে এবং সব সময় সব রিপো ঢেকে রাখে |
| `tags` / `favorites` / `groupOverrides` / `notes` / `archived` | প্রতি-রিপো সংগঠন |

`config.json`-এর পাশে আরও দুটি ফাইল থাকে, দুটোই নিশ্চিন্তে মুছে ফেলা যায় — repo-radar সেগুলো আবার বানিয়ে নেয়, শুধু খরচ আলাদা। `repo-cache.json` প্রতিটি রিপোর «ভারী» git ফিল্ড (stash, ট্যাগ, remote, মার্জ হয়ে যাওয়া ব্রাঞ্চ…) `.git`-এর একটি ফিঙ্গারপ্রিন্টের সঙ্গে বেঁধে মনে রাখে, ফলে না-বদলানো রিপো পরের স্ক্যানে ওই git কলগুলো এড়িয়ে যায়; এটি মুছলে পরের স্ক্যান কেবল একবার ধীর হয়। `repo-identity.json` হলো পরিচয়ের খতিয়ান, যার জোরে নাম বদলানো বা সরিয়ে নেওয়া রিপো একেবারে নতুন রিপো হিসেবে গণ্য না হয়ে তার ট্যাগ, স্টার, আর্কাইভ অবস্থা ও নোট ধরে রাখতে পারে। এখানে ক্ষতি স্থগিত নয়, তাৎক্ষণিক: ফাইলটি হারানোর **আগেই** যে রিপোর নাম বদলে গিয়েছিল বা যেটি সরে গিয়েছিল, সেটি পরের স্ক্যানেই একেবারে নতুন id পায়, আর তার ট্যাগ/স্টার/আর্কাইভ/নোট আটকে থাকে সেই id-র নিচে যা আর তার নয়। যেসব রিপোর নাম কখনও বদলায়নি সেগুলো অক্ষত থাকে, আর খতিয়ান আবার তৈরি হয়ে যাওয়ার পর থেকে নাম বদলানো ফের সুরক্ষিত।

`REPO_RADAR_CONFIG` ও `REPO_RADAR_PORT` (ডিফল্ট 17420) কনফিগ পাথ ও পোর্ট ওভাররাইড করে — সম্পূর্ণ স্বাধীন একটি দ্বিতীয় ইনস্ট্যান্স চালাতে **দুটোই** সেট করুন। সার্ভার কেবল `127.0.0.1`-এ বাইন্ড করে এবং প্রতিটি API ও WebSocket রিকোয়েস্টে Origin হেডার যাচাই করে।

ডিফল্ট পোর্ট ইচ্ছাকৃতভাবেই OS-এর ডায়নামিক পোর্ট রেঞ্জের উপরে রাখা: Windows ডিফল্টে 49152–65535 ব্যবহার করে, কিন্তু Hyper-V/WSL2 ইনস্টল থাকলে সেটা হয় 1024–15000, আর সিস্টেম সক্রিয় রেঞ্জ থেকে গোটা ব্লক সংরক্ষণ করে রাখে — সেই রেঞ্জের ভেতরের পোর্ট `EACCES` দিয়ে বাইন্ড হতে ব্যর্থ হয়, এবং রিবুটের সঙ্গে ব্লকগুলো সরে যায়।

**ডিফল্ট** পোর্টটিও বাইন্ড করা না গেলে repo-radar চালু হতে অস্বীকার না করে পরের প্রার্থীতে সরে যায় (`+1000`, `+2000`, `+3000`, তারপর OS-নির্ধারিত পোর্ট), যে পোর্টে থিতু হলো সেটি মনে রাখে এবং পরের বারগুলোতেও সেটিই ব্যবহার করে, আর ⚙ সেটিংসে ভার্সনের পাশে সেটি দেখায়। মনে রাখাটা জরুরি, কারণ পোর্ট পেজের origin-এর অংশ, আর বোর্ড সংরক্ষিত ভিউ, অ্যাক্টিভিটি লগ, থিম ও ভাষা রাখে origin-ভিত্তিক ব্রাউজার স্টোরেজে — পোর্ট এদিক-ওদিক লাফালে ওই ডেটা যেন হারিয়ে গিয়ে আবার ফিরে আসে। ডিফল্ট পোর্টে ফিরতে `<কনফিগ ডিরেক্টরি>/port-state.json` মুছে দিন।

`REPO_RADAR_PORT` দিয়ে নিজে সেট করা পোর্ট কখনোই বদলানো হয় না — সেটা আপনার বুকমার্ক, রিভার্স-প্রক্সি আপস্ট্রিম ও স্ক্রিপ্টের কাছে দেওয়া প্রতিশ্রুতি, তাই বাইন্ড না হলে সেটা স্পষ্টভাবে ব্যর্থ হয়। `npm run dev`-এও একই, কারণ vite-এর প্রক্সি টার্গেট কনফিগ লোডের সময়েই স্থির হয়ে যায়।

## ডেভেলপমেন্ট

```bash
npm run dev     # hot reload সহ vite + অ্যাপ উইন্ডো
npm test        # server + web + desktop টেস্ট স্যুট এবং টাইপচেক
npm run dist    # dist-electron/-এ ইনস্টলার বিল্ড করে
```

স্ট্যাক: Electron শেল + Node + Hono (সব git অপারেশন `spawn`-এর মাধ্যমে, শূন্য নেটিভ ডিপেন্ডেন্সি) + Vite / React 19 / antd 6, লাইভ আপডেটের জন্য chokidar + WebSocket সহ। Hono সার্ভার Electron-এর মেইন প্রসেসের ভেতরে চলে এবং উইন্ডোটি সেটিকে `127.0.0.1`-এর মাধ্যমে লোড করে, ফলে UI সম্পূর্ণরূপে সাধারণ HTTP + WebSocket — ব্রাউজারে চললে যেমন হতো ঠিক তেমন।
