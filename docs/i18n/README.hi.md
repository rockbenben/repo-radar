# repo-radar

> एक लोकल डैशबोर्ड जो आपके सभी Git रिपो पर नज़र रखता है और दिखाता है कि किन्हें आपकी ज़रूरत है।

आपके पास इतने Git repo हैं कि हाथ से हिसाब रखना मुश्किल है। repo-radar सब पर नज़र रखता है और वही चंद repo दिखाता है जिन्हें अभी आपकी ज़रूरत है — बाकी दिमाग़ से उतर सकते हैं।

वह चीज़ें सामने लाता है जिन्हें जाँचना आप वैसे भूल जाते:

- **अधूरा छूटा काम** — बिना commit, बिना push या stash में पड़े बदलाव, खोने से पहले चिह्नित।
- **GitHub आपका इंतज़ार कर रहा है** — खुले PR, issue और लाल CI, आपके पहले से लॉग-इन `gh` से पढ़े गए।
- **ठंडे पड़ते प्रोजेक्ट** — बहुत दिनों से अनछुए, या जिनकी रिलीज़ बाकी है।
- **नज़र से उतर चुके repo** — सब एक स्क्रीन पर, खोजने योग्य, एक क्लिक में खुलते हुए।

जिसे कार्रवाई चाहिए वह कतार बनकर ऊपर आ जाता है: हर repo का एक ही आइटम, ज़रूरत के क्रम में। ✓ से हटाइए और तब तक नहीं लौटेगा जब तक सचमुच कुछ बदल न जाए।

## समर्थन का दायरा

| पहलू | Windows | macOS | Linux |
| --- | --- | --- | --- |
| इंस्टॉल | `.exe` इंस्टॉलर | `.dmg` | `.AppImage` |
| विंडो बंद करने पर | ट्रे में चला जाता है | ट्रे में चला जाता है | बंद हो जाता है — बनाए रखने के लिए **लॉगिन पर शुरू करें** |
| बदलावों पर नज़र | स्कैन डायरेक्ट्री के नीचे के सभी repo | वही | पहले 200 repo (सीमा सेटिंग्स में बढ़ाई या हटाई जा सकती है) |

सब कुछ आपकी मशीन पर चलता है और वही `git` इस्तेमाल करता है जो पहले से आपके पास है — कोई खाता नहीं, कोई टेलीमेट्री नहीं, कुछ भी अपलोड नहीं। GitHub वाला हिस्सा (PR, issue, CI) वैकल्पिक है और उसी [`gh` CLI](https://cli.github.com/) से पढ़ता है जिसमें आप लॉग-इन हैं; उसके बिना भी बाकी सब चलता है।

## इंस्टॉल

अपने प्लेटफ़ॉर्म की फ़ाइल [Releases](https://github.com/rockbenben/repo-radar/releases) से लें — Node.js की ज़रूरत नहीं। ऐप कोड-साइन नहीं है, इसलिए पहली बार चलाने पर हर OS चेतावनी देता है:

- **Windows** — SmartScreen पर *More info → Run anyway*।
- **macOS** — पहली बार राइट-क्लिक → Open। अगर macOS इसे damaged बताए: `xattr -cr /Applications/repo-radar.app`।
- **Linux** — पहले `chmod +x repo-radar-*.AppImage`।

किसी बाइनरी पर यूँ ही भरोसा नहीं करना चाहते? [खुद बिल्ड कीजिए](../development.md) — बस `npm install && npm start`।

पहली बार चलाने पर **स्कैन डायरेक्ट्री जोड़ें** दबाइए और उस फ़ोल्डर को बताइए जिसके *अंदर* आपके repo पड़े हैं — जैसे `~/Projects`, न कि एक-एक repo। वह 6 स्तर नीचे तक `.git` वाली हर चीज़ ढूँढ़ता है और बोर्ड भर जाता है। न JSON, न रीस्टार्ट।

## बोर्ड

हर repo के लिए एक कार्ड — हेल्थ रंग, ब्रांच, वर्किंग ट्री का ब्यौरा, ahead/behind, आख़िरी commit, टैग — और हर कार्ड पर एक क्लिक में **एडिटर / टर्मिनल / फ़ोल्डर**।

- **ढूँढ़ना** — खोजिए, या भाषा, `#tag` या सिग्नल लैंप से छाँटिए। ⌘/Ctrl-K लॉन्चर खोलता है।
- **व्यू सहेजना** — कोई भी फ़िल्टर + क्रम + समूहन, नाम देकर दोबारा इस्तेमाल।
- **थोक में काम** — चुने हुए repo पर fetch / pull / push, या सब में एक ही shell कमांड। एक repo का फ़ेल होना बाक़ी को कभी नहीं रोकता।
- **वहीं काम निपटाना** — डिटेल पैनल लाइव diff के साथ commit करता है, ब्रांच बदलता है, बदलाव हटाता है, merge हो चुकी ब्रांचें साफ़ करता है, और माँगने पर GitHub PR व CI लाता है।
- **नया बनाना और हटाना-लाना** — **+ नया** repo बनाकर सीधे बोर्ड पर रख देता है; manifest एक्सपोर्ट / इम्पोर्ट आपकी सेटअप दूसरी मशीन पर ले जाता है।

ऊपर की लैंप अलर्ट के प्रकार हैं — कोई remote नहीं, बिना push, बिना commit, remote से पीछे, stash बचा हुआ। जो आपके काम के नहीं, उन्हें ⚙ Settings में बंद कर दीजिए।

दो और टैब: **आँकड़े** (साल भर का commit हीटमैप, सबसे सक्रिय और सबसे शांत) और **कार्य-लॉग** (किसी तिथि-सीमा को Markdown साप्ताहिक रिपोर्ट के रूप में कॉपी करें)।

गहरा इंस्ट्रूमेंट-कॉकपिट थीम, 18 भाषाओं में, और दोनों थीम में टेक्स्ट कंट्रास्ट WCAG AA के अनुसार।

## अद्यतन बने रहना

डिफ़ॉल्ट है हर 30 मिनट पर एक फ़ॉलबैक रीस्कैन और टूलबार से मैन्युअल रीस्कैन — लोकल, चुपचाप, बिना नेटवर्क।

फ़ाइल-वॉच से ऑटो-स्कैन **डिफ़ॉल्ट रूप से बंद** है और सेटिंग्स से चालू होता है। यह भी पूरी तरह लोकल है, पर जब कई प्रोजेक्ट एक साथ बिल्ड हो रहे हों तो कर्नेल का नोटिफ़िकेशन बफ़र लगातार भरकर छलकता है और हर बार एक रीस्कैन की क़ीमत पड़ती है — "क्या बदला ज़रा देख लूँ" वाले औज़ार के लिए यह स्थायी क़ीमत बहुत ज़्यादा है। चालू करने पर नया, हटाया गया या नाम बदला repo कुछ ही सेकंड में दिखता है।

repo का नाम बदलिए या उसे हटाकर कहीं और ले जाइए — उसके टैग, स्टार, आर्काइव स्थिति और नोट साथ रहते हैं। repo-radar repo को उसके भीतर मौजूद चीज़ से पहचानता है, इस से नहीं कि वह कहाँ रखा है; इसलिए जगह बदला फ़ोल्डर वही पुराना प्रोजेक्ट रहता है, नया नहीं।

निर्धारित बैकग्राउंड fetch वैकल्पिक है और अपने-आप नेटवर्क पर जाने वाली इकलौती सुविधा।

## पृष्ठभूमि में चुपचाप चलता है

विंडो बंद करने पर repo-radar ट्रे में चला जाता है, इसलिए रीस्कैन, निगरानी और GitHub अलर्ट चलते रहते हैं। बोर्ड वापस लाने के लिए ट्रे आइकन दबाइए, या ट्रे मेन्यू से पूरी तरह बंद कीजिए।

बंद होते समय वह पहले से चल रहे git काम — थोक pull, stash हटाना — के लिए 10 सेकंड तक रुकता है, ताकि लिखते-लिखते कुछ कटे नहीं और पुरानी `.git/index.lock` न छूट जाए। इतने में भी न हो तो वह फिर भी बंद हो जाता है और लॉग में यह बात लिख देता है।

**लॉगिन पर शुरू करें** चालू कीजिए, तो वह आपके सत्र के साथ बिना विंडो के शुरू होता है। डेस्कटॉप सूचनाएँ वैकल्पिक हैं और तभी बजती हैं जब कतार में कुछ *नया* आए।

## कॉन्फ़िगरेशन

स्कैन डायरेक्ट्री, बाहर रखे फ़ोल्डर और खोलने के कमांड ⚙ Settings → Scanning & open commands में बदले जा सकते हैं। बाक़ी सब `~/.repo-radar/config.json` में है, जिसे खोलने की ज़रूरत कम ही पड़ती है — पूरी फ़ील्ड सूची, उसके बग़ल की दो कैश फ़ाइलें और दूसरी इंस्टेंस चलाने के एन्वायरनमेंट वेरिएबल [कॉन्फ़िगरेशन संदर्भ](../configuration.md) में हैं।

## ज्ञात सीमाएँ

- **अपग्रेड जान-बूझकर मैन्युअल है।** ऑटो-अपडेट नहीं: नया इंस्टॉलर पुराने के ऊपर चला दीजिए।
- **हटाकर ले जाया गया repo अगले स्कैन में पहचाना जाता है — वह स्कैन चूक गया तो टैग साथ नहीं आते।** ड्राइव बदलकर की गई धीमी मूव, या ऐसी जगह जिसे आपने अभी स्कैन डायरेक्ट्री बनाया ही नहीं, नया कार्ड बनकर लौटती है और टैग पुराने कार्ड पर रह जाते हैं।
- **Linux पर भरोसेमंद ट्रे नहीं है**, इसलिए विंडो बंद करना ऐप बंद करना है।
- **स्कैन डायरेक्ट्री के बाहर एक-एक करके जोड़े गए repo इस तरह नहीं पहचाने जाते** — उन्हें हटाया तो नया पथ आप ख़ुद बताएँगे।
- **बदलाव हटाना submodule और भीतर बसे git repo को नहीं छूता**, और वह यह बात कहता है, सब साफ़ कर दिया ऐसा नहीं बताता।
