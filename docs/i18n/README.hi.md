# repo-radar

> 365 ओपन सोर्स प्लान #027 · एक लोकल Git रिपो डैशबोर्ड — एक क्रॉस-रिपो एक्शन क्यू जो बताता है कि अभी आपकी ज़रूरत किसे है।

एक लोकल Git रिपो डैशबोर्ड जो आपकी मशीन के हर रिपो को स्कैन करता है और सबसे पहले आपके सामने एक ही स्क्रीन रखता है: एक क्रॉस-रिपो **एक्शन क्यू** जो बताता है कि *अभी आपकी ज़रूरत किसे है* — किसी आइटम पर क्लिक करें और सीधे उस पर कार्रवाई करें। UI antd 6 पर बना है, एक गहरी इंस्ट्रूमेंट-कॉकपिट थीम के साथ।

## शुरुआत कैसे करें

```bash
npm install
npm run build   # build the frontend
npm start       # http://localhost:7420
```

पहली बार लॉन्च करने पर `~/.repo-radar/config.json` में एक डिफ़ॉल्ट कॉन्फ़िग बन जाती है। जिन डायरेक्टरी को स्कैन करवाना है उन्हें जोड़ने के लिए `roots` को एडिट करें (जैसे `D:\Projects` — JSON में बैकस्लैश को `D:\\Projects` की तरह एस्केप करें), फिर पैनल में **Rescan** पर क्लिक करें।

## Needs you (एंट्री स्क्रीन)

बोर्ड के सबसे ऊपर मौजूद **Needs you** क्यू एक क्रॉस-रिपो एक्शन क्यू है: तात्कालिकता के हिसाब से रैंक किया गया, प्रति रिपो एक आइटम — सबसे ज़रूरी एक चीज़, न कि "कितने कमिट हुए" जैसा एक और दिखावटी डैशबोर्ड।

- **Waiting on you**: दूसरों के खोले हुए PR, दूसरों के खोले हुए issue, डिफ़ॉल्ट ब्रांच पर लाल CI (यह सब बैकग्राउंड में एक लोकल, पहले से ऑथेंटिकेटेड `gh` के ज़रिए एकत्र होता है, हर 12 मिनट में रिफ्रेश होता है, या ↻ से मैन्युअली; आपके अपने खोले हुए PR/issue को WIP माना जाता है और उन्हें बाहर रखा जाता है) — किसी आइटम पर क्लिक करके सीधे संबंधित GitHub पेज पर जाएं
- **At risk of being lost**: कॉन्फ्लिक्ट / पीछे / अनकमिटेड / अनपुश्ड — ये जितनी देर पड़े रहें, रैंक उतनी ऊँची होती जाती है — अनपुश्ड काम के लिए एक-क्लिक पुश मिलता है, बाकी सब डिटेल पैनल खोलते हैं
- **Overdue for release**: जिन रिपो में टैग करने की आदत रही है और जिनमें आख़िरी टैग के बाद से बिना किसी रिलीज़ के ≥3 कमिट जमा हो चुके हैं — शिप करने के लिए एक हल्का इशारा (जो रिपो कभी टैग नहीं करते उन्हें छेड़ा नहीं जाता; आख़िरी टैग पूरे रिपो में क्रिएशन-टाइम के आधार पर चुना जाता है, वर्तमान ब्रांच से स्वतंत्र)
- **Forgotten stash**: ऐसा stash जो ≥7 दिनों से बिना छुए पड़ा है — क्लिक करके सीधे stash इनबॉक्स तक पहुँचें
- **Dismiss**: ✓ पर टैप करके किसी आइटम को तब तक हटाएं जब तक कुछ नया न हो — काउंट-आधारित आइटम के लिए काउंट बढ़ना ज़रूरी है, चेंज-आधारित आइटम के लिए एक और कमिट ज़रूरी है; stash को dismiss करना एक स्नूज़ है जो 30 दिन बाद फिर सामने आता है ताकि सचमुच भूला हुआ stash कभी हमेशा के लिए दब न जाए
- 10 से ज़्यादा आइटम देखने के लिए विस्तार करें; जब कुछ बचा न हो तो "all clear" दिखता है। यह ऊपर एक पतले बैनर में सिमट जाता है

## Board

- **Cards**: प्रति रिपो एक कार्ड (प्रति पंक्ति अधिकतम 4, समान ऊँचाई)। बायाँ किनारा रंग = स्वास्थ्य (हरा = शांत / एम्बर = ध्यान दें / लाल = अलर्ट)। असली नाम · विवरण · भाषा · ब्रांच (main न होने पर फ़्लैग्ड) · वर्किंग-ट्री का ब्यौरा (`+staged ~modified`) · आगे/पीछे · हेल्थ टैग · आख़िरी कमिट · रिमोट लिंक · टैग दिखाता है। फ़ुटर में हमेशा एक-क्लिक **editor / terminal / folder** मौजूद
- **Favorites row**: बोर्ड के ऊपर एक समर्पित "★ favorites" पंक्ति — क्लिक करने पर आपके एडिटर में खुलता है
- **Readout cluster**: टॉप बार में FLEET / CRIT / WARN / CLEAN गेज; अलर्ट की संख्या > 0 होने पर जल उठती है
- **Click to filter**: किसी कार्ड की भाषा या `#tag` पर क्लिक करें और वह सीधे सर्च बॉक्स में चला जाता है
- **Sort**: आख़िरी बार खोला गया / सबसे हाल में सक्रिय (कमिट समय के अनुसार) / नाम के अनुसार — favorites हमेशा सबसे ऊपर तैरते हैं
- **Attention lamps**: टॉप-बार चिप्स जो समस्याओं के प्रकार का सार देते हैं (कोई रिमोट नहीं / detached HEAD / अनपुश्ड / अनकमिटेड / पीछे / stash); फ़िल्टर करने के लिए क्लिक करें। "Unpushed" और "behind" दोनों में एक-क्लिक "push/pull all" मौजूद है
- **Grouping**: फ़ोल्डर के अनुसार / भाषा के अनुसार / बिना ग्रुप (flat)
- **Command palette ⌘/Ctrl-K**: एक लॉन्चर — नाम टाइप करें, एंटर दबाकर एडिटर में खोलें (terminal / folder / copy path / open remote के लिए इनलाइन बटन)
- **Tag filter**: टॉप बार में मल्टी-सिलेक्ट टैग (AND — हर चुना हुआ टैग होना ज़रूरी है); किसी कार्ड के `#tag` पर क्लिक करके उसे जोड़ें। Filter + sort + grouping एक साथ एक नामित "view" के रूप में सेव होते हैं
- **Inline preview**: कार्ड पर "⋯" डिटेल पैनल खोले बिना हाल के कमिट दिखाता है
- **Auto-scan (डिफ़ॉल्ट रूप से बंद)**: टॉप बार में "manual ⟳ / auto ⟳" टॉगल। चालू होने पर, एक file watcher प्रभावित कार्ड्स को अपने आप रिफ्रेश करता है (60-सेकंड का कूलडाउन; कूलडाउन के दौरान होने वाले बदलाव मर्ज होते हैं, कभी छूटते नहीं)। बंद होने पर, स्टेट सिर्फ़ Rescan पर अपडेट होती है। बोर्ड पहली बार लॉन्च होने पर भी एक स्कैन से भर जाता है
- **Scheduled fetch (डिफ़ॉल्ट रूप से बंद)**: टॉप बार में "fetch: off / every 5–60 min" — हर रिमोट को बैकग्राउंड में समय-समय पर fetch करता है ताकि ahead/behind की जानकारी ताज़ा रहे
- **18 भाषाएँ**: ⚙ Settings से UI की भाषा बदलें (सरलीकृत/पारंपरिक चीनी, अंग्रेज़ी, जापानी, कोरियाई, स्पैनिश, फ़्रेंच, जर्मन, पुर्तगाली, रूसी, इतालवी, अरबी, हिन्दी, बंगाली, थाई, तुर्की, वियतनामी, इंडोनेशियाई)। पहली बार बिना किसी सेव की गई प्राथमिकता के आने पर, UI अपने आप आपके ब्राउज़र की भाषा से मेल खाता है (कुछ न मिलने पर अंग्रेज़ी पर वापस आ जाता है); अरबी अपने आप RTL में बदल जाता है। सापेक्ष समय `Intl` के ज़रिए मूल रूप से स्थानीयकृत होते हैं। रिपो के नाम, विवरण और कमिट संदेश हमेशा बिना अनुवाद के रहते हैं

## Actions

- कार्ड के फ़ुटर में हमेशा editor / terminal / folder / copy-path बटन दिखते हैं; किसी एक को खोलने पर एक "last opened" टाइमस्टैम्प दर्ज होता है जो सॉर्टिंग में इस्तेमाल होता है
- Fetch / pull (`--ff-only`) / push बैच में चलते हैं: कई कार्ड चुनें → टॉप बार से बैच-एक्शन लें, या पूरे "unpushed" / "behind" attention lamp पर एक-क्लिक करें। प्रगति लाइव दिखती है; एक रिपो के फ़ेल होने पर बाकी नहीं रुकते
- **Run a command across repos**: कार्ड चुनें, टूलबार में एक कमांड टाइप करें (जैसे `npm install`), यह हर चुने हुए रिपो की डायरेक्टरी में समानांतर चलता है। "Dry run" पहले दिखाता है कि कौन-से रिपो प्रभावित होंगे; "view output" बाद में प्रति-रिपो नतीजा दिखाता है
- **Stash inbox**: कोई भी stash पड़ा होने पर, टॉप बार में "stash inbox (N)" लिंक दिखता है — हर रिपो में मौजूद हर stashed बदलाव को सूचीबद्ध करता है, प्रति-आइटम diff के साथ, `apply` / `pop` / `drop`
- कई कार्ड चुनने पर टैग को बल्क में भी लगाया जा सकता है
- **Manifest export / import**: बैकअप या मशीन बदलने के लिए **+ new** से पूरा रिपो मैनिफेस्ट (path + remotes + group + tags) एक्सपोर्ट करें; इम्पोर्ट करने पर पहले से मौजूद रिपो फिर से अपनाए जाते हैं और जो लोकली मौजूद नहीं हैं उन्हें clone करने के लिए सूचीबद्ध किया जाता है
- open कमांड को config.json में `open` के तहत प्रति-टारगेट कॉन्फ़िगर किया जा सकता है; `{path}` की जगह रिपो का path डाला जाता है
- **+ New**: अगला सीक्वेंस नंबर (जैसे `028-`) और आपके मौजूदा नंबरदार प्रोजेक्ट्स की पैरेंट डायरेक्टरी सुझाता है, फिर फ़ोल्डर बनाता है, `git init` चलाता है, एक README लिखता है, और उसे बोर्ड में फिर से स्कैन करता है

## Health checks & stats

- Rules (conflicted / no remote / detached HEAD / uncommitted / unpushed / untracked / behind / stash / stale) को `health.disabledRules` से अलग-अलग बंद किया जा सकता है; `staleDays` "stale" की सीमा तय करता है
- **Mergeable branches**: कार्ड्स दिखाते हैं कि कितने लोकल ब्रांच पहले ही HEAD में मर्ज हो चुके हैं (वर्तमान ब्रांच और main/master को छोड़कर); डिटेल पैनल एक-क्लिक `git branch -d` क्लीनअप देता है (यह हमेशा केवल पहले से मर्ज हो चुके ब्रांच को ही डिलीट करता है — सुरक्षित)
- **GitHub (वैकल्पिक, एक लोकल, पहले से ऑथेंटिकेटेड `gh` के ज़रिए)**: "needs you" क्यू हर `github.com` रिमोट के खुले PR / issue / डिफ़ॉल्ट-ब्रांच CI को बैकग्राउंड में एकत्र करता है (रेट-लिमिटेड पोलिंग, डिस्क पर संग्रहीत, रीस्टार्ट पर तुरंत उपलब्ध)। डिटेल पैनल मांग पर खुले-PR का विवरण और नवीनतम CI रन भी क्वेरी कर सकता है; उपलब्ध होने पर रिपो के विवरण GitHub से भर दिए जाते हैं
- **Stats** टैब: एक साल भर का क्रॉस-रिपो कमिट हीटमैप (केवल लोकल ब्रांच), सबसे हाल में सक्रिय, और सबसे लंबे समय से न छुए गए 10 रिपो
- **Worklog** टैब: एक तारीख़ की सीमा चुनकर क्रॉस-रिपो कमिट टाइमलाइन देखें (author के अनुसार फ़िल्टर करने योग्य — आपकी git पहचान अपने आप पहचानकर डिफ़ॉल्ट रूप से "only me" दिखाता है), एक-क्लिक में Markdown साप्ताहिक रिपोर्ट के रूप में कॉपी करने की सुविधा के साथ
- किसी कार्ड पर क्लिक करके डिटेल पैनल खोलें: पूरा हेल्थ ब्यौरा, mergeable branches, **लोकल ब्रांच बदलें / बनाएं / discard करें**, **कमिट इन प्लेस** (एक संदेश टाइप करें, यह कमिट कर देता है) पेंडिंग बदलावों के लाइव diff के साथ, GitHub PR/CI, एक मिनी 12-सप्ताह हीटमैप, हाल के कमिट, stashes, और remotes

## रिपो को व्यवस्थित करना

- किसी कार्ड को ★ से फ़ेवरिट करें (यह सबसे ऊपर आ जाता है); डिटेल पैनल में टैग जोड़ें/हटाएं (पहले इस्तेमाल किए गए टैग से ऑटोकम्प्लीट होता है) और उसका group बदलें ("auto" फ़ोल्डर-आधारित grouping वापस ले आता है)
- **Notes / to-dos**: डिटेल पैनल में "आगे क्या करना है" नोट कर लें — यह कार्ड पर दिखता है
- **Exclude**: जो रिपो नहीं देखने हैं उन्हें छुपाएं; एक्सक्लूड किए गए रिपो डिफ़ॉल्ट रूप से बोर्ड, अलर्ट, और command palette से छिप जाते हैं। टॉप बार में "Excluded (N)" उन्हें अलग से देखने/प्रबंधित करने देता है (डिटेल पैनल से un-exclude करें)
- बदलाव तुरंत लागू होते हैं और बिना कोई Git rescan ट्रिगर किए config.json में लिखे जाते हैं

## Development

```bash
npm run dev     # runs server(7420) + vite(5173) together, frontend proxies /api
npm test        # full server + web test suite + both typechecks
```

Stack: Node + Hono (सारी git एक्सेस `spawn` के ज़रिए, ज़ीरो नेटिव डिपेंडेंसी), Vite + React 19 + antd 6 (CSS वेरिएबल्स के ज़रिए गहराई से कस्टमाइज़्ड), लाइव अपडेट के लिए chokidar + WebSocket।

## Configuration (config.json)

| Field | Description |
| --- | --- |
| `roots` | स्कैन करने के लिए रूट डायरेक्टरी; `.git` वाली डायरेक्टरी को रिकर्सिवली खोजता है (गहराई ≤ 6) |
| `excludes` | छोड़ी जाने वाली डायरेक्टरी के नाम (डिफ़ॉल्ट में node_modules शामिल है) |
| `manualRepos` | मैन्युअल रूप से जोड़े गए रिपो path, कॉन्फ़िगर किए गए roots से बाहर |
| `tags` / `favorites` / `groupOverrides` | प्रति-रिपो-id टैग / फ़ेवरिट / group ओवरराइड |
| `notes` / `archived` | प्रति-रिपो-id नोट्स / archived फ़्लैग |
| `health` | `{ staleDays, disabledRules }` |
| `open` | एक-क्लिक open टारगेट (editor / terminal / explorer) के लिए कमांड टेम्पलेट |

`REPO_RADAR_CONFIG` एनवायरनमेंट वेरिएबल कॉन्फ़िग फ़ाइल के path को ओवरराइड करता है। सर्वर केवल `127.0.0.1` पर सुनता है और API व WebSocket दोनों पर Origin हेडर वेलिडेट करता है।
