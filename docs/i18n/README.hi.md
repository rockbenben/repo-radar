# repo-radar

> एक लोकल डैशबोर्ड जो आपके सभी Git रिपो पर नज़र रखता है और दिखाता है कि किन्हें आपकी ज़रूरत है।

आपके पास इतने Git रिपो हो गए हैं कि हाथ से सबका हिसाब रखना मुश्किल है। repo-radar उन सब पर नज़र रखता है और सिर्फ़ वही चंद रिपो सामने लाता है जिन्हें अभी आपकी ज़रूरत है — ताकि बाकी आपके दिमाग़ से उतर जाएँ।

जो चीज़ें आप वरना जाँचना भूल जाते, उन्हें यह सामने ले आता है:

- **वे रिपो जिनका आपसे हिसाब छूट गया** — आपके सभी रिपो एक ही स्क्रीन पर, सर्च की सुविधा के साथ, किसी को भी एक क्लिक में खोल लें।
- **अधूरा छूटा काम** — अनकमिटेड, अनपुश्ड, या स्टैश किए बदलाव, खोने से पहले ही चिह्नित।
- **GitHub आपके इंतज़ार में** — हर रिपो में खुले PR, issue और फ़ेल हुई CI, आपके लोकल, पहले से ऑथेंटिकेटेड `gh` के ज़रिए एक जगह जुटाए हुए।
- **सुस्त पड़ते प्रोजेक्ट** — जिन्हें बहुत समय से छुआ नहीं, या जिन्हें कब का शिप हो जाना चाहिए था।

जिन पर कार्रवाई ज़रूरी है वे एक क्यू की तरह बोर्ड में सबसे ऊपर आ जाते हैं — कितना ज़रूरी है उसी क्रम में, हर रिपो के लिए एक आइटम — सीधे उसी पर कार्रवाई करने के लिए क्लिक करें। ✓ दबाकर हटा दें, फिर जब तक सचमुच कुछ न बदले यह हटा ही रहता है; जब कुछ बाकी न हो तो "all clear" लिखा दिखता है। बाकी रिपो तो हमेशा बस एक सर्च की दूरी पर हैं।

## इंस्टॉल

[Releases](https://github.com/rockbenben/repo-radar/releases) से अपने प्लेटफ़ॉर्म की फ़ाइल लें — Node.js की ज़रूरत नहीं। ऐप कोड-साइन्ड नहीं है, इसलिए हर OS पहली बार चलाने पर चेतावनी देता है:

- **Windows** — `repo-radar-<version>-x64-setup.exe` चलाएं; SmartScreen प्रॉम्प्ट पर *More info → Run anyway* क्लिक करें।
- **macOS** — `repo-radar-<version>-arm64.dmg` खोलें और ऐप को Applications में खींच लाएं। पहली बार राइट-क्लिक → Open करें; अगर macOS इसे damaged कहे, तो `xattr -cr /Applications/repo-radar.app` से quarantine फ़्लैग एक बार साफ़ करें।
- **Linux** — `chmod +x repo-radar-<version>-x86_64.AppImage && ./repo-radar-<version>-x86_64.AppImage`।

या सोर्स से चलाएं:

```bash
npm install
npm start
```

पहली बार लॉन्च पर, **Add scan directories** (या ⚙ Settings → Scan directories) क्लिक करें और बता दें कि आपके रिपो किन फ़ोल्डरों में रखे हैं — न JSON, न रीस्टार्ट; सेव करते ही यह दोबारा स्कैन कर लेता है। अगर आप ख़ुद हाथ से एडिट करना चाहें तो सेटिंग्स `~/.repo-radar/config.json` में रहती हैं।

## बोर्ड

प्रति रिपो एक कार्ड — हेल्थ रंग, ब्रांच, वर्किंग-ट्री ब्रेकडाउन, ahead/behind, आख़िरी कमिट, टैग — हर कार्ड पर एक-क्लिक **editor / terminal / folder** के साथ। यहाँ से आप:

- **Find** — खोजें, किसी भाषा / `#tag` / attention-lamp पर क्लिक करके फ़िल्टर करें, सॉर्ट करें, और फ़ोल्डर या भाषा के अनुसार ग्रुप करें; किसी भी फ़िल्टर + सॉर्ट + ग्रुप को एक नामित view के रूप में सेव करें। ⌘/Ctrl-K एक लॉन्चर खोलता है।
- **Act in batches** — fetch / pull (`--ff-only`) / push करने के लिए रिपो चुनें, या उन पर समानांतर में एक शेल कमांड चलाएं (dry-run प्रिव्यू और प्रति-रिपो आउटपुट के साथ)। एक रिपो का फ़ेल होना बाकियों को कभी नहीं रोकता।
- **Dig into a repo** — डिटेल पैनल एक पूरा हेल्थ ब्यौरा देता है, ब्रांच switch / create / discard, लाइव diff के साथ **commit in place**, मांग पर GitHub PR और CI, हाल के कमिट, stashes, एक 12-सप्ताह हीटमैप, और पहले से मर्ज हो चुके ब्रांच की एक-क्लिक क्लीनअप — यह सिर्फ़ तब दिखाई जाती है जब आप `main`/`master` पर हों, क्योंकि केवल वहीं «पहले से मर्ज» का मतलब «ट्रंक में मर्ज» होता है। बदलाव discard करने पर ट्रैक हो रही फ़ाइलें वापस लौट आती हैं और अनट्रैक फ़ाइलें हट जाती हैं, लेकिन submodule की सामग्री और अनट्रैक नेस्टेड git रिपो को यह छूता नहीं; अगर कुछ बचा रह जाए तो यह सफल होने की रिपोर्ट देने के बजाय आपको वह बता देता है।
- **Stay fresh** — डिफ़ॉल्ट रिफ़्रेश का रास्ता है हर 30 मिनट का फ़ॉलबैक स्कैन और टूलबार से किया गया मैनुअल स्कैन। file-watch ऑटो-स्कैन **डिफ़ॉल्ट रूप से बंद** रहता है और ज़रूरत हो तो सेटिंग्स पैनल से खुद चालू करना होता है: यह सिर्फ़ लोकल है और नेटवर्क को कभी नहीं छूता, लेकिन जब कई प्रोजेक्ट एक साथ बिल्ड हो रहे हों तो कर्नेल का नोटिफ़िकेशन बफ़र लगातार ओवरफ़्लो होता है, और हर ओवरफ़्लो एक स्कैन की क़ीमत माँगता है — «क्या बदला, ज़रा देख लें» वाले औज़ार के लिए यह स्थायी क़ीमत बहुत ज़्यादा है। चालू करने पर, Windows और macOS पर हर स्कैन डायरेक्टरी के लिए एक ही रिकर्सिव वॉच उसके नीचे के सारे रिपो को कवर कर लेता है, इसलिए कोई रिपो जोड़ने, हटाने या नाम बदलने पर वह कुछ सेकंड में दिख जाता है; Linux पर रिपो अलग-अलग वॉच होते हैं और `watchLimit` (डिफ़ॉल्ट 200, 0 = कोई सीमा नहीं) उनकी संख्या सीमित करता है, जिसमें पसंदीदा और हाल में कमिट हुए रिपो को प्राथमिकता मिलती है। ओवरफ़्लो लगातार होता रहे तो भरपाई वाले स्कैन का अंतराल घातांकीय रूप से बढ़ता है (ज़्यादा से ज़्यादा हर 30 मिनट में एक) और वॉच हैंडल दोबारा नहीं बनाए जाते — वह सिर्फ़ तब होता है जब वॉच का लक्ष्य सचमुच गुम हो जाए। हर 30 मिनट का पूरा स्कैन वह उठा लेता है जो वॉच से छूट जाए, टूलबार में «पिछला स्कैन» दिखता है, और सेटिंग्स पैनल कवरेज लाइव दिखाता है («N में से M वॉच»)। किसी रिपो का नाम बदलने या उसे कहीं और ले जाने पर उसके टैग, स्टार, आर्काइव स्थिति और नोट्स बने रहते हैं — repo-radar सिर्फ़ पाथ नहीं, पहचान ट्रैक करता है। मिलान उस स्कैन दौर में होता है जो हटाने के **ठीक बाद** आता है, और इससे दो झिरियाँ बच जाती हैं: एक, वॉल्यूम के आर-पार धीमा मूव जो दो स्कैन दौरों में फैल जाए और बीच में किसी दूसरे रिपो का जुड़ना/हटना या नियमित पूरा स्कैन आ पड़े; दूसरी, ऐसा मूव जिसका गंतव्य उस दौर में स्कैन ही न हो — रिपो को अपनी स्कैन डायरेक्टरियों से बाहर ले जाना और उसकी नई जगह को बाद में स्कैन डायरेक्टरी के तौर पर जोड़ना इसमें फँसने का आम तरीका है। दोनों ही पाथ-आधारित पहचान पर लौट आते हैं: रिपो एक नए कार्ड की तरह वापस आता है, और उसके टैग/स्टार/आर्काइव/नोट्स उस id के नीचे छूट जाते हैं जो अब उसका नहीं है। शेड्यूल्ड बैकग्राउंड fetch खुद चालू करना होता है। एक **Stats** टैब (साल भर का कमिट हीटमैप, सबसे अधिक/सबसे कम सक्रिय) और एक **Worklog** टैब जो किसी तारीख़-सीमा को Markdown साप्ताहिक रिपोर्ट के रूप में कॉपी कर देता है।
- **Start & move repos** — **+ New** अगले नंबर वाला प्रोजेक्ट सुझाता है, `git init` चलाता है, एक README लिखता है, और उसे बोर्ड में अपना लेता है; manifest export / import आपके सेटअप को एक मशीन से दूसरी मशीन में ले जाता है।

UI antd 6 है, एक डार्क इंस्ट्रूमेंट-कॉकपिट थीम में, 18 भाषाओं में स्थानीयकृत (पहली बार आने पर आपके ब्राउज़र से स्वतः मेल, अरबी के लिए RTL)।

## बैकग्राउंड में चुपचाप चलता है

विंडो बंद करने पर repo-radar ट्रे में चला जाता है ताकि फ़ॉलबैक स्कैन, file-watching (अगर आपने इसे चालू किया हो), शेड्यूल्ड fetch और GitHub अलर्ट चलते रहें — बोर्ड वापस लाने के लिए ट्रे आइकॉन पर क्लिक करें, या ट्रे मेनू से असल में quit करें। (Linux पर, जहाँ डेस्कटॉप ट्रे भरोसेमंद नहीं होते, बंद करने पर यह ट्रे में जाने के बजाय quit ही हो जाता है; इसे चलता बनाए रखने के लिए Launch at login का इस्तेमाल करें।)

quit करते समय repo-radar पहले से चल रहे git काम — बैच pull, discard किया गया stash, शेड्यूल्ड fetch — के पूरा होने का 10 सेकंड तक इंतज़ार करता है, ताकि लिखाई के बीचोंबीच कुछ कटे नहीं और पीछे कोई पुराना `.git/index.lock` न छूटे। इतना समय काफ़ी न हो तो यह फिर भी बाहर निकल जाता है और यह बात लॉग में लिख देता है: बाद में मिलने वाले `index.lock` की वजह बताने वाली एकमात्र जगह वही है।

⚙ Settings में **Launch at login** ऑन करें और यह आपके सेशन के साथ हेडलेस शुरू होता है — जब तक आप न कहें तब तक कोई विंडो नहीं। वैकल्पिक डेस्कटॉप नोटिफ़िकेशन तभी आते हैं जब कोई *नई* चीज़ आपके क्यू में पहुँचती है, विंडो बंद होने पर भी। अपग्रेड जान-बूझकर मैन्युअल है (कोई ऑटो-अपडेट नहीं): नए इंस्टॉलर को पुराने पर चला दें। लॉग `<config dir>/logs/repo-radar.log` में जमा होते हैं।

## कॉन्फ़िगरेशन

UI जो कुछ भी छूता है वह सब `~/.repo-radar/config.json` में सेव होता है — इसे खोलने की ज़रूरत आपको शायद ही कभी पड़े। जो फ़ील्ड मायने रखते हैं:

| फ़ील्ड | यह क्या करता है |
| --- | --- |
| `roots` / `excludes` / `manualRepos` | कहाँ स्कैन करना है (`.git` को 6 गहराई तक खोजता है, symlink के पीछे नहीं जाता), क्या छोड़ना है, और roots के बाहर जोड़े गए रिपो — `manualRepos` की जिस एंट्री का नाम बदल जाए या जो कहीं और चली जाए, वह स्कैन किए गए रिपो की तरह पहचान से ट्रैक नहीं होती; जब तक आप यहाँ उसका पाथ अपडेट न करें, कार्ड एरर में रहता है, और अगर मूव एक स्कैन दौर से भी पहले हुआ था तो वह अपडेट कार्ड वापस लाता है, उसके टैग/स्टार/आर्काइव/नोट्स नहीं |
| `health` | `{ staleDays, disabledRules }` — "stale" थ्रेशहोल्ड ट्यून करें या अलग-अलग चेक बंद करें |
| `open` | editor / terminal / folder बटन के कमांड टेम्पलेट (`{path}` = रिपो पाथ) |
| `autoWatch` / `autoScanMinutes` / `watchLimit` / `autoFetchMinutes` / `notifications` | बैकग्राउंड व्यवहार — डिफ़ॉल्ट रूप से सिर्फ़ `autoScanMinutes` (30) चालू है; `autoWatch` समेत बाकी तीन बंद हैं। `watchLimit` (200, 0 = कोई सीमा नहीं) **सिर्फ़ Linux पर** लागू होता है, जहाँ रिपो अलग-अलग वॉच होते हैं; Windows और macOS हर स्कैन डायरेक्टरी के लिए एक रिकर्सिव वॉच इस्तेमाल करते हैं और हमेशा सारे रिपो कवर करते हैं |
| `tags` / `favorites` / `groupOverrides` / `notes` / `archived` | प्रति-रिपो संगठन |

`config.json` के बगल में दो और फ़ाइलें रहती हैं, दोनों बेझिझक हटाई जा सकती हैं — repo-radar उन्हें फिर बना लेता है, बस क़ीमत अलग-अलग है। `repo-cache.json` हर रिपो के «भारी» git फ़ील्ड (stashes, टैग, remotes, मर्ज हो चुके ब्रांच…) को `.git` के फ़िंगरप्रिंट से जोड़कर याद रखता है, जिससे न बदले हुए रिपो अगले स्कैन में वे git कॉल छोड़ देते हैं; इसे हटाने पर अगला स्कैन बस एक बार धीमा हो जाता है। `repo-identity.json` पहचान का बही-खाता है, जिसकी वजह से नाम बदले या हटाए गए रिपो को बिल्कुल नया रिपो मानने के बजाय उसके टैग, स्टार, आर्काइव स्थिति और नोट्स बचे रहते हैं। यहाँ नुक़सान टलता नहीं, तुरंत होता है: फ़ाइल खोने से **पहले** जिस भी रिपो का नाम बदल चुका था या जो हट चुका था, उसे अगले ही स्कैन में बिल्कुल नई id मिलती है, और उसके टैग/स्टार/आर्काइव/नोट्स उस id के नीचे अटके रह जाते हैं जो अब उसका नहीं है। जिन रिपो का नाम कभी बदला ही नहीं, वे अछूते रहते हैं, और बही-खाता फिर बन जाने के बाद से नाम बदलना दोबारा सुरक्षित हो जाता है।

`REPO_RADAR_CONFIG` और `REPO_RADAR_PORT` (डिफ़ॉल्ट 17420) कॉन्फ़िग पाथ और पोर्ट को ओवरराइड करते हैं — एक अलग, पूरी तरह स्वतंत्र दूसरा इंस्टेंस चलाने के लिए **दोनों** सेट करें। सर्वर केवल `127.0.0.1` पर बाइंड करता है और हर API व WebSocket रिक्वेस्ट पर Origin हेडर वेलिडेट करता है।

डिफ़ॉल्ट पोर्ट जान-बूझकर OS की डायनैमिक पोर्ट रेंज से ऊपर रखा गया है: Windows डिफ़ॉल्ट रूप से 49152–65535 इस्तेमाल करता है, लेकिन Hyper-V/WSL2 इंस्टॉल होते ही 1024–15000, और सिस्टम सक्रिय रेंज में से पूरे ब्लॉक आरक्षित कर लेता है — उसके भीतर का पोर्ट `EACCES` के साथ बाइंड होने में विफल रहता है, और ये ब्लॉक हर रीबूट पर खिसकते हैं।

**डिफ़ॉल्ट** पोर्ट भी बाइंड न हो पाए तो repo-radar शुरू होने से इनकार करने के बजाय अगले विकल्प पर चला जाता है (`+1000`, `+2000`, `+3000`, फिर OS द्वारा दिया गया पोर्ट), जिस पोर्ट पर टिका उसे याद रखता है और आगे के लॉन्च में वही इस्तेमाल करता है, और ⚙ सेटिंग्स में वर्ज़न के बगल में दिखाता है। याद रखना ज़रूरी है क्योंकि पोर्ट पेज के origin का हिस्सा है, और बोर्ड सहेजे गए व्यू, गतिविधि लॉग, थीम और भाषा को origin-आधारित ब्राउज़र स्टोरेज में रखता है — पोर्ट को इधर-उधर उछलने देने से वह डेटा गायब होकर लौटता हुआ दिखेगा। डिफ़ॉल्ट पोर्ट पर लौटने के लिए `<कॉन्फ़िग डायरेक्टरी>/port-state.json` हटा दें।

`REPO_RADAR_PORT` से आपका खुद तय किया पोर्ट कभी नहीं बदला जाता — वह आपके बुकमार्क, रिवर्स-प्रॉक्सी अपस्ट्रीम और स्क्रिप्ट से किया वादा है, इसलिए बाइंड न होने पर वह साफ़-साफ़ विफल होता है। `npm run dev` में भी यही, क्योंकि vite का प्रॉक्सी लक्ष्य कॉन्फ़िग लोड के समय ही तय हो जाता है।

## डेवलपमेंट

```bash
npm run dev     # hot reload के साथ vite + ऐप विंडो
npm test        # server + web + desktop टेस्ट सूट और टाइपचेक
npm run dist    # dist-electron/ में इंस्टॉलर बिल्ड करता है
```

Stack: Electron शेल + Node + Hono (सारे git ऑपरेशन `spawn` के ज़रिए, ज़ीरो नेटिव डिपेंडेंसी) + Vite / React 19 / antd 6, लाइव अपडेट के लिए chokidar + WebSocket के साथ। Hono सर्वर Electron की main प्रोसेस के अंदर चलता है और विंडो इसे `127.0.0.1` से लोड करती है, यानी UI पूरी तरह सादा HTTP + WebSocket है — बिल्कुल वैसा ही जैसा ब्राउज़र में होता है।
