# repo-radar

> 一個本機面板，替你盯著所有 Git 儲存庫，告訴你其中哪些需要你出手。

你的 Git 儲存庫多到光靠腦子已經記不過來。repo-radar 替你盯著全部，只把此刻需要你處理的那幾個挑出來——其餘的就別再掛心了。

它替你翻出那些你本來會忘記去查的東西：

- **沒做完的活** —— 未提交、未推送或擱進 stash 的改動，在你弄丟它們之前標出來。
- **GitHub 在等你** —— open PR、issue 和變紅的 CI，透過你本機已登入的 `gh` 讀取。
- **正在長草的專案** —— 太久沒碰的，或是早該發版的。
- **你已經顧不過來的儲存庫** —— 全部在一屏之內，可搜尋，點一下就能開啟。

需要動手的會升到最前面形成一條佇列，一個儲存庫一條，按緊迫度排序。點 ✓ 消掉後就不再出現，直到確實有變化才回來。

## 支援範圍

| 方面 | Windows | macOS | Linux |
| --- | --- | --- | --- |
| 安裝 | `.exe` 安裝程式 | `.dmg` | `.AppImage` |
| 關閉視窗 | 收進系統匣 | 收進系統匣 | 直接結束——用**開機自動啟動**讓它常駐 |
| 改動監聽 | 掃描目錄下的儲存庫全覆蓋 | 同左 | 覆蓋前 200 個儲存庫（上限可在設定裡調高或取消）|

一切都在你本機執行，用的就是你機器上那個 `git`——不需要帳號，沒有埋點，什麼都不上傳。GitHub 那一欄（PR、issue、CI）是選用的，讀的是你已經登入好的 [`gh` CLI](https://cli.github.com/)；不用它，其餘功能照常。

## 安裝

從 [Releases](https://github.com/rockbenben/repo-radar/releases) 下載對應平台的檔案——不需要 Node.js。應用未做程式碼簽章，因此每個系統首次執行都會告警：

- **Windows** —— 在 SmartScreen 提示上點擊 *其他資訊 → 仍要執行*。
- **macOS** —— 首次請右鍵 → 開啟。如果 macOS 說它已損毀：`xattr -cr /Applications/repo-radar.app`。
- **Linux** —— 先 `chmod +x repo-radar-*.AppImage`。

不想憑信任接受一個二進位檔？[自己編譯一份](../development.md)——就是 `npm install && npm start`。

首次啟動點 **新增掃描目錄**，指向你的儲存庫所在的那個**上層目錄**——比如 `D:\Projects`，而不是逐個新增儲存庫。它會向下找 6 層以內帶 `.git` 的目錄，看板隨即填滿。不必碰 JSON，也不用重啟。

## 看板

每個儲存庫一張卡片——健康度色帶、分支、工作區細分、ahead/behind、上次提交、標籤——每張卡都帶一鍵 **編輯器 / 終端 / 目錄**。

- **找到它** —— 搜尋，或按語言、`#tag`、告警燈篩選。⌘/Ctrl-K 開啟啟動器。
- **存成視圖** —— 任意篩選 + 排序 + 分組，命名後反覆用。
- **批次操作** —— 對選取的儲存庫 fetch / pull / push，或在它們裡面執行同一條 shell 指令。單個失敗絕不拖住其餘的。
- **就地處理** —— 詳情面板帶即時 diff 提交、切換分支、丟棄改動、清理已合併分支，並按需拉取 GitHub PR 與 CI。
- **新增與遷移** —— **＋新增** 直接建好儲存庫並納入看板；清單匯出 / 匯入讓設定在不同機器間遷移。

頂部那排燈就是告警類型——無遠端、未推送、未提交、落後遠端、遺留 stash。用不上的可以在 ⚙ 設定裡關掉。

另有兩個分頁：**統計**（一年的提交熱力圖、最活躍與最不活躍）和 **工作記錄**（把某個日期範圍複製成 Markdown 週報）。

深色儀表艙主題，在地化為 18 種語言，深淺兩套主題的文字對比度均依 WCAG AA 校準。

## 保持最新

預設方式是 30 分鐘一輪的兜底重掃，加上頂部工具列的手動重掃——純本機、安靜、不走網路。

檔案監聽自動掃描**預設關閉**，可在設定裡自行開啟。它同樣純本機，但幾個專案同時在跑建置時核心通知緩衝區會持續溢位，每次溢位都要補一輪重掃——對一個「看一眼哪裡變了」的工具來說，這筆常駐開銷不值得。開啟後，新增、刪除或改名的儲存庫幾秒內就能被發現。

改名或搬移一個儲存庫，它的標籤、收藏、封存狀態和便箋都會保留。repo-radar 靠儲存庫內部的內容認人，不靠它放在哪裡，所以換個位置它還是原來那個專案，而不是新的一個。

定時背景 fetch 需自行開啟，也是唯一會主動連網的功能。

## 在背景安靜執行

關閉視窗只會把 repo-radar 收進系統匣，重掃、監聽和 GitHub 提醒都繼續跑。點系統匣圖示把看板喚回，或從系統匣選單真正結束。

結束時會等已經在跑的 git 操作收尾——批次 pull、丟棄 stash——上限 10 秒，以免寫入被切斷、留下一個過期的 `.git/index.lock`。等不到也會照樣結束，並在日誌裡說明。

打開 **開機自動啟動**，它就隨你的工作階段無介面啟動。選用的桌面通知只在有*新*項目進入佇列時才觸發。

## 設定

掃描目錄、排除目錄和開啟方式可以在 ⚙ 設定 → 掃描與開啟方式 裡改。其餘設定都在 `~/.repo-radar/config.json`，你很少需要開啟它——完整欄位表、旁邊那兩個快取檔案、以及用來跑第二實例的環境變數，見[設定參考](../configuration.md)。

## 已知限制

- **升級是刻意設計的手動方式。** 沒有自動更新：用新安裝程式覆蓋舊的即可。
- **搬走的儲存庫靠緊接著那一輪掃描認回來——錯過那一輪，標籤就跟不過去了。** 跨磁碟的慢速搬移，或新位置你還沒加進掃描目錄，都會讓它以一張全新卡片回來，標籤留在舊的那張上。
- **Linux 上沒有可靠的系統匣**，所以關閉視窗等於結束。
- **一個個手動新增、不在掃描目錄裡的儲存庫，不走這套識別** —— 搬走之後要你自己指向新路徑。
- **丟棄改動不動 submodule 和巢狀的 git 儲存庫**，並且會如實說明，而不是報成功。
