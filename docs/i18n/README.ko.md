# repo-radar

> 모든 Git 저장소를 지켜보며 그중 어느 것에 당신의 손이 필요한지 알려주는 로컬 대시보드.

손으로 챙기기엔 Git 저장소가 너무 많습니다. repo-radar는 전부를 지켜보다가 지금 손이 필요한 몇 개만 보여줍니다——나머지는 잊고 지내도 됩니다.

그냥 두면 확인을 잊게 되는 것들을 끌어올립니다:

- **끝내지 못한 작업** —— 커밋·푸시하지 않았거나 stash에 넣어둔 변경을, 잃어버리기 전에 표시합니다.
- **GitHub가 기다리는 일** —— 열린 PR, 이슈, 실패한 CI를 이미 로그인된 `gh`로 읽어옵니다.
- **방치되는 프로젝트** —— 너무 오래 손대지 않았거나, 릴리스가 밀린 것들.
- **놓치고 있던 저장소** —— 전부 한 화면에, 검색 가능하게, 한 번의 클릭으로.

손이 필요한 항목은 큐로 맨 위에 올라옵니다. 저장소당 한 건, 급한 순서대로. ✓로 지우면 실제로 상황이 바뀌기 전까지 돌아오지 않습니다. 단 stash만 예외라서 30일이 지나면 다시 올라옵니다. 정말 잊어버린 stash가 영영 사라지지 않게 하려는 장치입니다.

## 지원 범위

| 항목 | Windows | macOS | Linux |
| --- | --- | --- | --- |
| 설치 | `.exe` 설치 프로그램 | `.dmg` | `.AppImage` |
| 창을 닫으면 | 트레이로 | 트레이로 | 종료됩니다——상주시키려면 **로그인 시 시작** |
| 변경 감시 | 스캔 디렉터리 아래 전체 저장소 | 동일 | 앞의 200개까지(설정에서 상한을 올리거나 해제)|

모두 내 컴퓨터에서 돌아가고, 이미 설치된 `git`을 씁니다——계정 없음, 텔레메트리 없음, 아무것도 올라가지 않습니다. GitHub 열(PR·이슈·CI)은 선택이며 로그인된 [`gh` CLI](https://cli.github.com/)로 읽습니다. 쓰지 않아도 나머지는 그대로 동작합니다.

## 설치

[Releases](https://github.com/rockbenben/repo-radar/releases)에서 플랫폼에 맞는 파일을 받으세요——Node.js는 필요 없습니다. 코드 서명이 없어 각 OS가 첫 실행 때 경고합니다:

- **Windows** —— SmartScreen에서 *추가 정보 → 실행*.
- **macOS** —— 처음엔 우클릭 → 열기. 손상되었다고 하면 `xattr -cr /Applications/repo-radar.app`.
- **Linux** —— 먼저 `chmod +x repo-radar-*.AppImage`.

바이너리를 그냥 믿기 어렵다면 [직접 빌드](../development.md)하세요——`npm install && npm start`면 됩니다.

처음 실행하면 **스캔 디렉터리 추가**를 눌러 저장소들이 *들어 있는* 상위 폴더(`~/Projects` 같은)를 지정하세요. 하나씩 추가하는 게 아닙니다. 거기서 6단계까지 내려가며 `.git`이 있는 곳을 찾아 보드를 채웁니다. JSON도, 재시작도 필요 없습니다.

## 보드

저장소당 카드 한 장——상태 색, 브랜치, 작업 트리 내역, ahead/behind, 마지막 커밋, 태그——카드마다 **에디터 / 터미널 / 폴더** 원클릭.

- **찾기** —— 검색하거나 언어, `#tag`, 신호등으로 거릅니다. ⌘/Ctrl-K로 런처.
- **뷰 저장** —— 필터 + 정렬 + 그룹을 이름 붙여 재사용.
- **일괄 처리** —— 선택한 저장소에 fetch / pull / push, 또는 같은 셸 명령을 한 번에. 하나가 실패해도 나머지는 멈추지 않습니다.
- **그 자리에서 처리** —— 상세 패널에서 라이브 diff로 커밋, 브랜치 전환, 변경 폐기, 병합된 브랜치 정리, GitHub PR·CI 조회.
- **만들고 옮기기** —— **＋새로 만들기**는 저장소를 만들어 바로 보드에 올립니다. 매니페스트 내보내기 / 가져오기는 저장소 목록——경로, 원격, 그룹, 태그——을 다른 기기로 옮깁니다.

상단의 램프가 경고 종류입니다——원격 없음, HEAD 분리, 미푸시, 미커밋, 원격보다 뒤처짐, stash 남음. 필요 없는 건 ⚙ 설정에서 끌 수 있습니다.

탭이 둘 더 있습니다: **통계**(1년치 커밋 히트맵, 가장 활발한 / 뜸한 저장소)와 **작업 기록**(기간을 Markdown 주간 보고로 복사).

어두운 계기판 테마, 18개 언어, 라이트·다크 두 테마 모두 텍스트 대비를 WCAG AA에 맞췄습니다.

## 최신 상태 유지

기본값은 30분마다의 폴백 재스캔과 툴바의 수동 재스캔입니다. 재스캔은 로컬 git 상태만 읽습니다——무엇이 바뀌었는지 알아보려고 원격에 연락하지 않습니다.

파일 감시 자동 스캔은 **기본값이 꺼짐**이며 설정에서 켭니다. 이것도 로컬 전용이지만, 여러 프로젝트가 동시에 빌드 중이면 커널 알림 버퍼가 계속 넘치고, 넘칠 때마다 이벤트가 사라져 더는 신뢰할 수 없습니다——유일하게 안전한 대응은 재스캔 한 번 더이며, 지수 백오프로 최대 30분에 한 번까지 제한됩니다. 그래도 "뭐가 바뀌었는지 한 번 본다"는 도구에 상시로 치르기엔 비쌉니다. 켜면 저장소의 추가·삭제·이름 변경이 몇 초 안에 반영됩니다.

저장소의 이름을 바꾸거나 옮겨도 태그, 즐겨찾기, 보관 상태, 메모는 그대로입니다. repo-radar는 안에 든 내용으로 저장소를 알아보지 위치로 알아보지 않기 때문에, 옮겨도 새 프로젝트가 아니라 같은 프로젝트입니다.

예약된 백그라운드 fetch는 선택 사항이며, 스스로 원격과 대화하는 유일한 기능입니다. GitHub 열만이 시키지 않아도 시간에 맞춰 네트워크로 나갑니다——`gh` CLI가 설치돼 있는 동안 PR, issue, CI는 그것을 통해 12분마다, 그리고 재스캔 직후에 갱신됩니다. `gh`가 없거나 GitHub 원격이 없으면 앱은 완전히 로컬입니다.

## 백그라운드에서 조용히

Windows와 macOS에서는 창을 닫으면 트레이로 내려가 재스캔, 감시, GitHub 알림이 계속 돌아갑니다. Linux에서는 창을 닫으면 앱이 끝납니다——그쪽엔 믿을 만한 트레이가 없습니다. Windows와 Linux에서는 트레이 아이콘 클릭으로 보드를 부르고, macOS에서는 아이콘이 메뉴를 열면 거기가 첫 항목입니다——종료도 모든 플랫폼에서 그 메뉴 안에 있습니다.

종료할 때는 진행 중인 git 작업——일괄 pull, stash 삭제——을 최대 10초 기다립니다. 쓰기 도중에 끊겨 `.git/index.lock`이 남지 않도록요. 그래도 부족하면 그냥 종료하고 로그에 남깁니다.

**로그인 시 시작**을 켜면 세션과 함께 창 없이 뜹니다. 데스크톱 알림은 선택이고, GitHub의 “너를 기다리는 항목”에 *새* 항목이 들어올 때만 울립니다 — PR, issue, 실패한 CI. 처음 로드할 때는 울리지 않습니다.

## 설정

스캔 디렉터리, 제외 폴더, 열기 명령은 ⚙ 설정 → 스캔 및 열기 명령에서 바꿉니다. 나머지는 `~/.repo-radar/config.json`에 있고 열 일은 거의 없습니다. 순수 표시 선택(저장한 보기, 테마, 언어, 활동 기록)은 브라우저 저장소에 있습니다. 전체 필드, 옆에 있는 캐시 파일, 두 번째 인스턴스를 띄우는 환경 변수는 [설정 레퍼런스](../configuration.md)를 보세요.

## 알려진 한계

- **업그레이드는 의도적으로 수동입니다.** 자동 업데이트 없음: 새 설치 프로그램을 덮어 실행하세요.
- **인식하는 스캔을 지나친 이동은 조용한 상실이 아니라 힌트를 남깁니다.** 자동 대조가 실패하면 새 카드가 “옛 경로를 옮긴 것으로 보입니다”를 띄웁니다 — **이관**을 누르면 태그, 즐겨찾기, 메모가 따라옵니다. 힌트는 이 설치본에서 최소 한 번 스캔돼 대장에 원격이 기록된 저장소에서만 뜨고, 스캔 디렉터리에 추가하지 않은 목적지에서는 뜨지 않습니다.
- **Linux에는 믿을 만한 트레이가 없어** 창을 닫으면 종료됩니다.
- **스캔 디렉터리 밖에서 하나씩 추가한 저장소는 이 방식으로 인식되지 않습니다** —— 옮겼다면 경로를 직접 다시 지정해야 합니다.
- **변경 폐기는 서브모듈과 중첩된 git 저장소를 건드리지 않으며**, 전부 지웠다고 하지 않고 그 사실을 알려줍니다.
