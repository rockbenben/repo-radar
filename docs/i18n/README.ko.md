# repo-radar

> 모든 Git 저장소를 지켜보며 그중 어느 것에 당신의 손이 필요한지 알려주는 로컬 대시보드.

손으로 일일이 챙기기엔 Git 저장소가 너무 많습니다. repo-radar가 그 모두를 지켜보며 지금 당신의 손이 필요한 몇 개만 골라 보여줍니다 — 나머지는 머릿속에서 지워도 됩니다.

그냥 두면 확인하는 걸 잊어버릴 것들을 대신 끄집어냅니다:

- **놓쳐버린 저장소** — 당신이 가진 모든 저장소를 한 화면에, 검색 가능하며, 어느 것이든 클릭 한 번으로 엽니다.
- **끝내지 못한 작업** — 미커밋 · 미푸시 · stash된 변경을 잃어버리기 전에 표시해 줍니다.
- **GitHub가 당신을 기다림** — 모든 저장소에 걸친 열린 PR, 이슈, 실패한 CI를 로컬에 이미 인증된 `gh`를 통해 모아 옵니다.
- **정체되어 가는 프로젝트** — 너무 오래 손대지 않았거나, 출시가 늦어진 것들.

손이 필요한 것들은 큐로서 보드 맨 위로 떠오르며, 긴급도 순으로 정렬되고, 저장소당 한 항목만 — 클릭하면 바로 처리할 수 있습니다. ✓로 지우면 실제로 무언가 바뀌기 전까지 사라진 채로 있고, 기다리는 게 없으면 "all clear"라고 표시됩니다. 나머지 저장소는 언제나 검색 한 번이면 찾을 수 있습니다.

## 설치

[Releases](https://github.com/rockbenben/repo-radar/releases)에서 사용 중인 플랫폼용 파일을 받으세요 — Node.js는 필요 없습니다. 앱은 코드 서명되어 있지 않아 각 OS가 처음 실행할 때 경고를 표시합니다:

- **Windows** — `repo-radar-<version>-x64-setup.exe`를 실행하세요. SmartScreen 프롬프트에서 *추가 정보 → 실행*을 클릭합니다.
- **macOS** — `repo-radar-<version>-arm64.dmg`를 열고 앱을 Applications로 드래그하세요. 처음에는 우클릭 → 열기; macOS가 손상되었다고 하면 `xattr -cr /Applications/repo-radar.app`으로 격리 속성을 한 번 지우세요.
- **Linux** — `chmod +x repo-radar-<version>-x86_64.AppImage && ./repo-radar-<version>-x86_64.AppImage`.

또는 소스에서 실행:

```bash
npm install
npm start
```

처음 실행할 때 **스캔 디렉터리 추가**(또는 ⚙ 설정 → 스캔 디렉터리)를 클릭하고 저장소가 들어 있는 폴더를 가리키게 하세요 — JSON도, 재시작도 필요 없이 저장하는 순간 다시 스캔합니다. 직접 편집하고 싶다면 설정은 `~/.repo-radar/config.json`에 있습니다.

## 보드

저장소당 카드 하나 — 상태 색상, 브랜치, 워킹트리 변경 내역, ahead/behind, 마지막 커밋, 태그 — 모든 카드에 클릭 한 번으로 실행하는 **editor / terminal / folder**가 있습니다. 여기서 당신은:

- **찾기** — 검색하고, 언어 / `#tag` / 주의 표시등을 클릭해 필터링하며, 폴더나 언어로 정렬·그룹화합니다. 어떤 필터 + 정렬 + 그룹화든 이름 붙인 뷰로 저장할 수 있습니다. ⌘/Ctrl-K로 런처가 열립니다.
- **일괄 작업** — 저장소를 선택해 fetch / pull(`--ff-only`) / push하거나, 그 저장소들에 걸쳐 셸 명령을 병렬로 실행합니다(dry-run 미리보기와 저장소별 출력 포함). 저장소 하나가 실패해도 나머지는 멈추지 않습니다.
- **저장소 파고들기** — 상세 패널은 전체 상태 내역, 브랜치 전환 / 생성 / 폐기, 실시간 diff와 함께하는 **그 자리에서 커밋**, 필요 시 GitHub PR & CI, 최근 커밋, stash, 12주 히트맵, 그리고 이미 병합된 브랜치를 클릭 한 번으로 정리하는 기능을 제공합니다 — 이 정리는 `main`/`master`에 있을 때만 제시됩니다. 「이미 병합됨」이 「트렁크에 병합됨」과 일치하는 위치는 그곳뿐이기 때문입니다. 변경 폐기는 추적 중인 파일을 되돌리고 추적되지 않는 파일을 삭제하지만, 서브모듈 내용과 추적되지 않는 중첩 git 저장소는 건드리지 않습니다. 폐기하지 못한 것이 남아 있으면 성공이라고 보고하지 않고 그 사실을 알려 줍니다.
- **최신 유지** — 기본 갱신 경로는 30분마다 도는 재스캔과 툴바의 수동 재스캔입니다. 파일 감시 자동 스캔은 **기본으로 꺼져 있으며** 설정 패널에서 직접 켭니다. 로컬 전용이라 네트워크를 쓰지 않지만, 여러 프로젝트가 동시에 빌드 중이면 커널 알림 버퍼가 계속 넘치고 넘칠 때마다 재스캔을 한 번씩 치러야 합니다 — 「무엇이 바뀌었는지 한눈에 보는」 도구가 늘 치르기엔 비싼 값입니다. 켜면 Windows와 macOS에서는 스캔 디렉터리마다 재귀 감시 핸들 하나로 그 아래 모든 저장소를 커버하므로, 저장소를 추가·삭제·이름 변경하면 몇 초 안에 반영됩니다. Linux에서는 저장소를 개별로 감시하며 `watchLimit`(기본 200, 0 = 무제한)이 감시 수를 제한하고 즐겨찾기와 최근 커밋된 저장소를 우선합니다. 넘침이 계속되면 보충 재스캔은 간격을 지수적으로 늘리고(최대 30분에 한 번) 감시 핸들을 다시 만들지도 않습니다 — 다시 만드는 것은 감시 대상이 실제로 사라졌을 때뿐입니다. 감시가 놓친 변경은 30분마다 도는 재스캔이 받아 주고, 툴바에 「마지막 스캔」이 표시되며, 설정 패널에는 「N개 중 M개 감시」 커버리지가 실시간으로 표시됩니다. 저장소의 이름을 바꾸거나 옮겨도 태그·별·보관 상태·메모는 유지됩니다 — repo-radar가 추적하는 것은 경로가 아니라 저장소의 정체성입니다. 대조는 이동 **직후의 스캔 회차**에서 이루어지므로 두 가지 빈틈이 남습니다. 하나는 볼륨을 넘나드는 느린 이동이 두 스캔 회차에 걸치고 그 사이에 다른 저장소의 추가·삭제나 주기적 재스캔이 끼어드는 경우입니다. 다른 하나는 이동한 곳이 그 회차에 스캔되지 않는 경우로, 저장소를 스캔 디렉터리 밖으로 옮긴 뒤 나중에 그 새 위치를 스캔 디렉터리로 추가하는 것이 대표적입니다. 둘 다 경로 기반 식별로 되돌아가며, 저장소는 새 카드로 나타나고 태그/별/보관/메모는 더 이상 갖고 있지 않은 id 아래에 남습니다. 예약된 백그라운드 fetch는 직접 켜야 합니다. 그리고 **Stats** 탭(1년치 커밋 히트맵, 가장 활발한/가장 덜 활발한)과 날짜 범위를 Markdown 주간 보고서로 복사하는 **Worklog** 탭이 있습니다.
- **저장소 생성 및 이동** — **+ New**는 다음 번호 프로젝트를 제안하고 `git init`을 실행하며 README를 작성해 보드에 편입시킵니다. 매니페스트 내보내기 / 가져오기로 설정을 여러 머신 사이에서 옮길 수 있습니다.

UI는 어두운 계기판(instrument-cockpit) 테마의 antd 6이며, 18개 언어로 현지화되어 있습니다(첫 방문 시 브라우저에 자동 매칭, 아랍어는 RTL).

## 백그라운드에서 조용히 실행

창을 닫으면 repo-radar는 트레이로 내려가 재스캔, 파일 감시(켜 두었다면), 예약된 fetch, GitHub 알림을 계속 실행합니다 — 트레이 아이콘을 클릭하면 보드가 돌아오고, 완전히 종료하려면 트레이 메뉴에서 종료하세요. (데스크톱 트레이를 믿기 어려운 Linux에서는 닫기가 곧 종료입니다. 상주시키려면 로그인 시 시작을 사용하세요.)

종료할 때는 이미 실행 중인 git 작업 — 일괄 pull, stash 폐기, 예약된 fetch — 이 끝나기를 최대 10초 기다립니다. 쓰기 도중에 끊겨 오래된 `.git/index.lock`이 남지 않도록 하기 위함입니다. 그 시간으로 부족하면 그대로 종료하고 그 사실을 로그에 남깁니다. 나중에 `index.lock`을 만났을 때 이유를 설명해 주는 것은 그 한 줄뿐입니다.

⚙ 설정에서 **로그인 시 시작**을 켜면 세션과 함께 창 없이 시작합니다 — 당신이 부를 때까지 창은 나타나지 않습니다. 선택적인 데스크톱 알림은 *새로운* 무언가가 큐에 도착할 때만, 창이 닫혀 있어도 발생합니다. 업그레이드는 의도적으로 수동입니다(자동 업데이트 없음): 새 설치 파일을 기존 것 위에 실행하세요. 로그는 `<config dir>/logs/repo-radar.log`에 남습니다.

## 설정

UI가 건드리는 모든 것은 `~/.repo-radar/config.json`에 저장됩니다 — 열어볼 일은 드뭅니다. 중요한 필드:

| 필드 | 하는 일 |
| --- | --- |
| `roots` / `excludes` / `manualRepos` | 어디를 스캔할지(깊이 6까지 `.git` 탐색, 심볼릭 링크는 따라가지 않음), 무엇을 건너뛸지, roots 밖에서 추가한 저장소 — `manualRepos` 항목은 이름이 바뀌거나 옮겨져도 스캔된 저장소처럼 정체성으로 추적되지 않으므로, 여기서 경로를 갱신할 때까지 카드는 오류 상태입니다. 이동 후 스캔 회차가 한 번 이상 지난 뒤에 갱신하면 카드는 돌아오지만 태그/별/보관/메모는 돌아오지 않습니다 |
| `health` | `{ staleDays, disabledRules }` — "stale" 임계값을 조정하거나 개별 검사를 비활성화 |
| `open` | editor / terminal / folder 버튼의 명령 템플릿(`{path}` = 저장소 경로) |
| `autoWatch` / `autoScanMinutes` / `watchLimit` / `autoFetchMinutes` / `notifications` | 백그라운드 동작 — 기본으로 켜진 것은 `autoScanMinutes`(30분)뿐이고 `autoWatch`를 포함한 나머지 셋은 꺼짐. `watchLimit`(200, 0 = 무제한)은 **Linux에서만 적용**되며, 그곳에서는 저장소를 개별로 감시합니다. Windows와 macOS는 스캔 디렉터리마다 재귀 감시 하나를 사용해 항상 모든 저장소를 커버합니다 |
| `tags` / `favorites` / `groupOverrides` / `notes` / `archived` | 저장소별 정리 정보 |

`config.json` 옆에 파일이 두 개 더 있으며, 둘 다 안심하고 삭제할 수 있습니다 — repo-radar가 다시 만들지만 대가는 다릅니다. `repo-cache.json`은 각 저장소의 「무거운」 git 필드(stash, 태그, 리모트, 병합된 브랜치 등)를 `.git` 지문에 묶어 기억하므로, 변경되지 않은 저장소는 다음 재스캔에서 그 git 호출들을 건너뛸 수 있습니다. 삭제하면 다음 재스캔이 한 번 느려질 뿐입니다. `repo-identity.json`은 정체성 원장으로, 이름이 바뀌거나 옮겨진 저장소가 완전히 새 저장소로 취급되는 대신 태그·별·보관 상태·메모를 지킬 수 있게 해 줍니다. 이쪽의 삭제는 손실이 미뤄지지 않고 즉시 발생합니다. 파일이 사라지기 **전에** 이미 이름이 바뀌거나 옮겨졌던 저장소는 바로 다음 스캔에서 새 id를 받고, 그 태그/별/보관/메모는 더 이상 갖고 있지 않은 id 아래에 남습니다. 한 번도 이름이 바뀌지 않은 저장소는 영향이 없고, 원장이 다시 만들어지면 그 이후의 이름 변경은 다시 보호됩니다.

`REPO_RADAR_CONFIG`와 `REPO_RADAR_PORT`(기본 17420)는 설정 경로와 포트를 재정의합니다 — **둘 다** 설정하면 완전히 독립된 두 번째 인스턴스를 실행할 수 있습니다. 서버는 `127.0.0.1`에만 바인딩하고, 모든 API와 WebSocket 요청에서 Origin 헤더를 검증합니다.

기본 포트는 의도적으로 OS 동적 포트 범위 위쪽에 둡니다. Windows는 기본적으로 49152–65535를 쓰지만 Hyper-V/WSL2를 설치하면 1024–15000이 되고, 시스템은 활성 범위에서 블록 단위로 포트를 예약합니다 — 그 안의 포트는 `EACCES`로 바인드에 실패하며, 예약 블록은 재부팅마다 옮겨 다닙니다.

**기본** 포트마저 바인드되지 않으면 repo-radar는 실행을 거부하는 대신 다음 후보(`+1000`, `+2000`, `+3000`, 마지막은 OS 할당 포트)로 넘어가고, 자리 잡은 포트를 기억해 이후 실행에서도 그대로 쓰며, ⚙ 설정의 버전 옆에 표시합니다. 기억이 중요한 이유는 포트가 페이지 origin의 일부이기 때문입니다 — 저장한 뷰, 활동 로그, 테마, 언어가 origin 단위 브라우저 저장소에 들어 있어서, 포트가 오락가락하면 그 데이터가 사라졌다 돌아오는 것처럼 보입니다. 기본 포트로 되돌리려면 `<설정 디렉터리>/port-state.json`을 지우세요.

`REPO_RADAR_PORT`로 직접 지정한 포트는 절대 대체되지 않습니다 — 북마크, 리버스 프록시 업스트림, 스크립트에 대한 약속이기 때문입니다. 바인드할 수 없으면 분명하게 실패합니다. `npm run dev`도 마찬가지로, vite의 프록시 대상은 설정 로드 시점에 고정됩니다.

## 개발

```bash
npm run dev     # vite + 핫 리로드 되는 앱 창
npm test        # server + web + desktop 테스트 스위트와 타입체크
npm run dist    # dist-electron/ 에 설치 파일 빌드
```

스택: Electron 셸 + Node + Hono(모든 git은 `spawn`을 통해, 네이티브 의존성 없음) + Vite / React 19 / antd 6, 실시간 업데이트를 위한 chokidar + WebSocket. Hono 서버는 Electron의 메인 프로세스 안에서 실행되고 창은 `127.0.0.1`을 통해 그것을 불러오므로, UI는 평범한 HTTP + WebSocket입니다 — 브라우저에서 돌아가는 것과 똑같습니다.
