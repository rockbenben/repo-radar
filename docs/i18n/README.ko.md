# repo-radar

> 365 오픈소스 프로젝트 #027 · 로컬 Git 저장소 대시보드 — 지금 당장 내 손이 필요한 일이 무엇인지 알려주는, 여러 저장소를 아우르는 작업 큐

내 컴퓨터에 있는 모든 저장소를 스캔해 화면 하나에 가장 먼저 보여주는 로컬 Git 저장소 대시보드입니다. 여러 저장소를 아우르는 **작업 큐(action queue)** 가 지금 당장 내 손이 필요한 일이 무엇인지 알려주며, 항목을 클릭하면 바로 처리할 수 있습니다. UI는 antd 6 기반으로, 계기판(instrument-cockpit) 느낌의 짙은 테마로 구성되어 있습니다.

## 빠른 시작

```bash
npm install
npm run build   # build the frontend
npm start       # http://localhost:7420
```

처음 실행하면 `~/.repo-radar/config.json`에 기본 설정 파일이 생성됩니다. `roots`를 편집해서 스캔하고 싶은 디렉터리를 추가한 뒤(예: `D:\Projects` — JSON에서는 백슬래시를 `D:\\Projects`처럼 이스케이프해야 합니다), 패널에서 **Rescan**을 클릭하세요.

## Needs you (진입 화면)

보드 맨 위에 있는 **Needs you** 큐는 여러 저장소를 아우르는 작업 큐입니다. 긴급도 순으로 정렬되며 저장소당 딱 하나의 항목만 보여줍니다 — "커밋이 몇 개인가" 같은 허영 지표가 아니라, 가장 시급한 단 하나의 일만 보여줍니다.

- **Waiting on you**: 다른 사람이 올린 열린 PR, 다른 사람이 올린 열린 이슈, 기본 브랜치의 실패한 CI(로컬에 이미 인증된 `gh`를 통해 백그라운드에서 12분마다 집계되며, ↻로 수동 새로고침도 가능 — 본인이 올린 열린 PR/이슈는 진행 중(WIP)으로 간주되어 제외됩니다) — 항목을 클릭하면 해당 GitHub 페이지로 바로 이동합니다
- **At risk of being lost**: 충돌 / 뒤처짐(behind) / 미커밋 / 미푸시 상태이며, 오래 방치될수록 순위가 올라갑니다 — 미푸시 작업은 클릭 한 번으로 푸시할 수 있고, 나머지는 상세 패널이 열립니다
- **Overdue for release**: 태그를 붙이는 습관이 있는 저장소인데 최신 태그 이후 커밋이 3개 이상 쌓였는데도 릴리스가 없는 경우 — 출시를 재촉하는 알림입니다(태그를 아예 붙이지 않는 저장소는 건드리지 않습니다. 최신 태그는 현재 브랜치와 무관하게 저장소 전체에서 생성 시각 기준으로 선정됩니다)
- **Forgotten stash**: 7일 이상 손대지 않은 stash — 클릭하면 stash 수신함으로 바로 이동합니다
- **Dismiss**: ✓를 눌러 새로운 변화가 생길 때까지 항목을 지웁니다 — 개수 기반 항목은 개수가 늘어나야 하고, 변경 기반 항목은 커밋이 하나 더 있어야 다시 나타납니다. stash를 닫는 것은 30일 후 다시 떠오르는 일시 정지(snooze)이므로, 정말 잊힌 stash가 영영 묻히는 일은 없습니다
- 10개를 넘으면 펼쳐서 전체를 볼 수 있고, 남은 항목이 없으면 "all clear"가 표시됩니다. 상단에서는 얇은 배너로 접힙니다

## Board

- **카드**: 저장소당 카드 하나(행당 최대 4개, 높이는 동일). 왼쪽 테두리 색으로 상태를 표시(초록 = 조용함 / 호박색 = 주의 필요 / 빨강 = 경고). 실제 이름 · 설명 · 언어 · 브랜치(main이 아니면 표시) · 워킹트리 변경 내역(`+staged ~modified`) · ahead/behind · 상태 태그 · 마지막 커밋 · 원격 링크 · 태그를 보여줍니다. 하단에는 항상 클릭 한 번으로 실행하는 **editor / terminal / folder** 버튼이 있습니다
- **즐겨찾기 행**: 보드 상단에 전용 "★ favorites" 행이 있어 클릭하면 에디터에서 바로 열립니다
- **계기판(readout cluster)**: 상단 바에 있는 FLEET / CRIT / WARN / CLEAN 게이지 — 경고 개수가 0보다 크면 불이 켜집니다
- **클릭으로 필터링**: 카드의 언어나 `#tag`를 클릭하면 바로 검색창에 들어갑니다
- **정렬**: 마지막으로 연 순 / 최근 활동 순(커밋 시간 기준) / 이름순 — 즐겨찾기는 항상 맨 위에 고정됩니다
- **주의 표시등(Attention lamps)**: 이슈 유형을 요약하는 상단 바 칩(원격 없음 / detached HEAD / 미푸시 / 미커밋 / behind / stash) — 클릭하면 필터링됩니다. "Unpushed"와 "behind"는 각각 클릭 한 번으로 "전체 push/pull"이 가능합니다
- **그룹화**: 폴더별 / 언어별 / 그룹 없음(평면)
- **커맨드 팔레트 ⌘/Ctrl-K**: 런처입니다 — 이름을 입력하고 엔터를 누르면 에디터에서 열립니다(터미널 / 폴더 / 경로 복사 / 원격 열기용 인라인 버튼도 제공)
- **태그 필터**: 상단 바에서 태그를 다중 선택(AND 조건 — 선택한 태그를 모두 가지고 있어야 함); 카드의 `#tag`를 클릭하면 추가됩니다. 필터 + 정렬 + 그룹화는 이름이 붙은 "view"로 함께 저장됩니다
- **인라인 미리보기**: 카드의 "⋯"를 누르면 상세 패널을 열지 않고도 최근 커밋을 팝업으로 볼 수 있습니다
- **자동 스캔(기본 꺼짐)**: 상단 바의 "manual ⟳ / auto ⟳" 토글. 켜면 파일 감시기(watcher)가 영향받은 카드를 자동으로 새로고침합니다(60초 쿨다운, 쿨다운 중 발생한 변경 사항은 병합되며 절대 누락되지 않습니다). 끄면 Rescan을 눌러야만 상태가 갱신됩니다. 처음 실행 시에는 자동/수동 여부와 무관하게 한 번 스캔되어 보드가 채워집니다
- **예약 fetch(기본 꺼짐)**: 상단 바의 "fetch: off / every 5–60 min" — 백그라운드에서 주기적으로 모든 원격을 fetch하여 ahead/behind 정보를 최신 상태로 유지합니다
- **18개 언어**: ⚙ 설정에서 UI 언어를 전환할 수 있습니다(중국어 간체/번체, 영어, 일본어, 한국어, 스페인어, 프랑스어, 독일어, 포르투갈어, 러시아어, 이탈리아어, 아랍어, 힌디어, 벵골어, 태국어, 터키어, 베트남어, 인도네시아어). 저장된 설정이 없는 첫 방문에서는 브라우저 언어에 자동으로 맞춰지며(일치하는 언어가 없으면 영어로 대체), 아랍어를 선택하면 RTL로 자동 전환됩니다. 상대 시간은 `Intl`을 통해 네이티브로 현지화됩니다. 저장소 이름, 설명, 커밋 메시지는 항상 번역되지 않은 원문 그대로 표시됩니다

## Actions

- 카드 하단에는 항상 editor / terminal / folder / copy-path 버튼이 표시되며, 하나를 열면 정렬에 사용되는 "마지막으로 연 시각"이 기록됩니다
- Fetch / pull(`--ff-only`) / push는 배치 단위로 실행됩니다: 카드를 여러 개 선택한 뒤 상단 바에서 배치 작업을 실행하거나, "unpushed" / "behind" 주의 표시등을 클릭 한 번으로 전체 처리할 수 있습니다. 진행 상황은 실시간으로 표시되며, 저장소 하나가 실패해도 나머지는 계속 진행됩니다
- **여러 저장소에서 명령 실행**: 카드를 선택하고 툴바에 명령을 입력하면(예: `npm install`) 선택된 모든 저장소 디렉터리 안에서 병렬로 실행됩니다. "Dry run"으로 어떤 저장소가 영향을 받는지 먼저 미리 볼 수 있고, "view output"으로 이후 저장소별 결과를 확인할 수 있습니다
- **Stash 수신함**: stash가 하나라도 있으면 상단 바에 "stash inbox (N)" 링크가 나타납니다 — 모든 저장소에 걸친 stash 변경 사항을 목록으로 보여주며, 항목별 diff와 `apply` / `pop` / `drop`을 제공합니다
- 카드를 여러 개 선택하면 태그를 일괄 적용할 수도 있습니다
- **매니페스트 내보내기/가져오기**: **+ new**에서 전체 저장소 매니페스트(경로 + 원격 + 그룹 + 태그)를 내보내 백업하거나 다른 머신으로 옮길 수 있습니다. 가져올 때는 로컬에 이미 존재하는 저장소는 다시 채택하고, 없는 저장소는 클론 대상으로 목록에 표시합니다
- 열기 명령은 config.json의 `open` 아래에서 대상별로 설정할 수 있으며, `{path}`는 저장소 경로로 치환됩니다
- **+ New**: 다음 순번(예: `028-`)과 기존에 번호가 매겨진 프로젝트들의 상위 디렉터리를 제안한 뒤, 폴더를 만들고 `git init`을 실행하고 README를 작성한 다음 보드에 다시 스캔해 넣습니다

## Health checks & stats

- 규칙(충돌 / 원격 없음 / detached HEAD / 미커밋 / 미푸시 / 미추적 / behind / stash / stale)은 `health.disabledRules`를 통해 개별적으로 비활성화할 수 있으며, `staleDays`는 "stale" 판정 기준을 설정합니다
- **병합 가능한 브랜치**: 카드에는 이미 HEAD에 병합된 로컬 브랜치의 개수가 표시됩니다(현재 브랜치와 main/master는 제외). 상세 패널에서 클릭 한 번으로 `git branch -d` 정리를 실행할 수 있습니다(이미 병합된 브랜치만 삭제하므로 안전합니다)
- **GitHub(선택 사항, 로컬에 이미 인증된 `gh` 사용)**: "needs you" 큐는 모든 `github.com` 원격에 대해 열린 PR / 이슈 / 기본 브랜치 CI를 백그라운드에서 집계합니다(속도 제한이 적용된 폴링, 디스크에 저장되어 재시작 시 즉시 표시). 상세 패널에서도 필요할 때 열린 PR의 세부 정보와 최신 CI 실행 결과를 조회할 수 있으며, 가능한 경우 GitHub에서 저장소 설명을 채워 넣습니다
- **Stats** 탭: 1년치 저장소 통합 커밋 히트맵(로컬 브랜치만), 가장 최근에 활동한 저장소, 가장 오래 손대지 않은 저장소 10개를 보여줍니다
- **Worklog** 탭: 날짜 범위를 선택해 여러 저장소를 아우르는 커밋 타임라인을 볼 수 있습니다(작성자로 필터링 가능 — git 아이디를 자동 감지해 기본값은 "나만 보기"). 클릭 한 번으로 Markdown 주간 보고서 형식으로 복사할 수 있습니다
- 카드를 클릭하면 상세 패널이 열립니다: 전체 상태 내역, 병합 가능한 브랜치, **로컬 브랜치 전환/생성/폐기**, **그 자리에서 커밋**(메시지를 입력하면 커밋됨), 대기 중인 변경 사항의 실시간 diff, GitHub PR/CI, 12주짜리 미니 히트맵, 최근 커밋, stash, 원격 정보를 볼 수 있습니다

## 저장소 정리

- 카드에 ★를 눌러 즐겨찾기로 지정하면 맨 위로 올라갑니다. 상세 패널에서 태그를 추가/제거하고(이미 사용한 태그로 자동 완성됨), 그룹을 변경할 수 있습니다("auto"로 설정하면 폴더 기반 그룹화로 복원됩니다)
- **메모 / 할 일**: 상세 패널에 "다음에 할 일"을 적어두면 카드에 표시됩니다
- **제외**: 보고 싶지 않은 저장소를 숨깁니다 — 제외된 저장소는 기본적으로 보드, 알림, 커맨드 팔레트에서 숨겨집니다. 상단 바의 "Excluded (N)"에서 별도로 확인/관리할 수 있습니다(상세 패널에서 제외 해제 가능)
- 변경 사항은 즉시 적용되며 Git 재스캔을 유발하지 않고 config.json에 기록됩니다

## Development

```bash
npm run dev     # runs server(7420) + vite(5173) together, frontend proxies /api
npm test        # full server + web test suite + both typechecks
```

스택: Node + Hono(모든 git 접근은 `spawn`을 통해 이루어지며 네이티브 의존성 없음), Vite + React 19 + antd 6(CSS 변수로 깊게 커스터마이징), 실시간 업데이트를 위한 chokidar + WebSocket.

## Configuration (config.json)

| 필드 | 설명 |
| --- | --- |
| `roots` | 스캔할 루트 디렉터리; `.git`이 포함된 디렉터리를 재귀적으로 탐색(깊이 ≤ 6) |
| `excludes` | 건너뛸 디렉터리 이름(기본값에 node_modules 포함) |
| `manualRepos` | 설정된 roots 외부에서 수동으로 추가한 저장소 경로 |
| `tags` / `favorites` / `groupOverrides` | 저장소별 태그 / 즐겨찾기 / 그룹 오버라이드 |
| `notes` / `archived` | 저장소별 메모 / 보관 플래그 |
| `health` | `{ staleDays, disabledRules }` |
| `open` | 클릭 한 번으로 여는 대상(editor / terminal / explorer)에 대한 명령 템플릿 |

`REPO_RADAR_CONFIG` 환경 변수를 사용하면 설정 파일 경로를 재정의할 수 있습니다. 서버는 `127.0.0.1`에서만 리스닝하며, API와 WebSocket 모두에서 Origin 헤더를 검증합니다.
