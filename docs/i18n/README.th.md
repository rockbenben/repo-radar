# repo-radar

> โครงการ 365 Open Source #027 · แดชบอร์ด Git repo ในเครื่อง — คิวงานข้ามทุก repo ที่ตอบคำถามว่าตอนนี้มีอะไรต้องให้คุณจัดการบ้าง

แดชบอร์ด Git repo ในเครื่องที่สแกนทุกโปรเจกต์บนเครื่องของคุณ แล้วนำเสนอหน้าจอเดียวที่สำคัญที่สุดให้เห็นก่อน นั่นคือ **คิวงานที่ต้องทำ (action queue)** ข้ามทุก repo ที่ตอบคำถามว่า *ตอนนี้มีอะไรต้องให้คุณจัดการบ้าง* — คลิกรายการแล้วลงมือทำได้ทันที ส่วน UI สร้างด้วย antd 6 พร้อมธีมสไตล์ห้องนักบิน (instrument cockpit) ที่เข้มขลัง

## เริ่มต้นใช้งานอย่างรวดเร็ว

```bash
npm install
npm run build   # build the frontend
npm start       # http://localhost:7420
```

เมื่อเปิดใช้งานครั้งแรก ระบบจะสร้างไฟล์ config เริ่มต้นไว้ที่ `~/.repo-radar/config.json` แก้ไข `roots` เพื่อเพิ่มไดเรกทอรีที่ต้องการให้สแกน (เช่น `D:\Projects` — ต้อง escape backslash เป็น `D:\\Projects` ในรูปแบบ JSON) จากนั้นคลิก **Rescan** ในแผงควบคุม

## Needs you (หน้าจอเริ่มต้น)

คิว **Needs you** ที่อยู่ด้านบนสุดของบอร์ดคือคิวงานข้ามทุก repo ที่จัดอันดับตามความเร่งด่วน หนึ่งรายการต่อหนึ่ง repo — แสดงเฉพาะเรื่องเร่งด่วนที่สุดเพียงเรื่องเดียว ไม่ใช่แดชบอร์ดโอ้อวดแบบ "มีกี่คอมมิต"

- **Waiting on you**: PR ที่เปิดค้างจากคนอื่น, issue ที่เปิดค้างจากคนอื่น, CI สีแดงบน default branch (รวบรวมแบบพื้นหลังผ่าน `gh` ที่ล็อกอินอยู่แล้วในเครื่อง รีเฟรชทุก 12 นาที หรือกด ↻ ด้วยตัวเองก็ได้ ส่วน PR/issue ที่คุณเปิดเองจะถูกนับเป็นงานที่ทำอยู่ (WIP) และไม่ถูกนำมาแสดง) — คลิกรายการเพื่อไปยังหน้า GitHub ที่ตรงกันโดยตรง
- **At risk of being lost**: มีความขัดแย้ง (conflict) / ตามหลัง (behind) / ยังไม่ commit / ยังไม่ push — ยิ่งค้างนานยิ่งถูกจัดอันดับสูงขึ้น งานที่ยังไม่ push จะมีปุ่ม push แบบคลิกเดียว ส่วนที่เหลือจะเปิดแผงรายละเอียด
- **Overdue for release**: repo ที่มีนิสัยชอบติด tag แต่สะสมคอมมิตตั้งแต่ tag ล่าสุดไว้ ≥3 คอมมิตโดยยังไม่ปล่อยรุ่นใหม่ — เป็นการเตือนให้ปล่อยรุ่น (repo ที่ไม่เคยติด tag เลยจะไม่ถูกนำมานับ โดย tag ล่าสุดจะพิจารณาจากเวลาที่สร้างทั่วทั้ง repo โดยไม่ขึ้นกับ branch ปัจจุบัน)
- **Forgotten stash**: stash ที่ถูกทิ้งไว้ไม่แตะต้องเกิน 7 วัน — คลิกเพื่อไปยัง stash inbox โดยตรง
- **Dismiss**: แตะ ✓ เพื่อล้างรายการออกจนกว่าจะมีอะไรใหม่เกิดขึ้น — รายการที่นับจากจำนวนต้องรอให้จำนวนเพิ่มขึ้นอีก รายการที่นับจากการเปลี่ยนแปลงต้องรอคอมมิตใหม่อีกครั้ง ส่วนการ dismiss stash เป็นการเลื่อนแจ้งเตือน (snooze) ที่จะกลับมาแสดงอีกครั้งหลัง 30 วัน เพื่อไม่ให้ stash ที่ถูกลืมจริง ๆ เงียบหายไปตลอดกาล
- ขยายดูเกิน 10 รายการเพื่อดูทั้งหมด และจะแสดงข้อความ "all clear" เมื่อไม่มีอะไรเหลือ ยุบเหลือเป็นแถบบาง ๆ ด้านบนได้

## Board

- **Cards**: หนึ่งการ์ดต่อหนึ่ง repo (สูงสุด 4 การ์ดต่อแถว ความสูงเท่ากัน) สีขอบด้านซ้าย = สถานะสุขภาพ (เขียว = ปกติ / เหลือง = ต้องระวัง / แดง = แจ้งเตือน) แสดงชื่อจริง · คำอธิบาย · ภาษา · branch (มีป้ายเตือนถ้าไม่ใช่ main) · สรุป working tree (`+staged ~modified`) · ahead/behind · แท็กสถานะสุขภาพ · คอมมิตล่าสุด · ลิงก์ remote · แท็ก ส่วนท้ายมีปุ่มคลิกเดียวสำหรับ **editor / terminal / folder** เสมอ
- **Favorites row**: แถว "★ favorites" เฉพาะที่อยู่ด้านบนสุดของบอร์ด — คลิกเพื่อเปิดใน editor
- **Readout cluster**: มาตรวัด FLEET / CRIT / WARN / CLEAN บนแถบด้านบน จำนวนแจ้งเตือนจะติดสว่างเมื่อมากกว่า 0
- **Click to filter**: คลิกภาษาหรือ `#tag` บนการ์ดเพื่อใส่ลงในช่องค้นหาทันที
- **Sort**: เปิดล่าสุด / ใช้งานล่าสุด (ตามเวลาคอมมิต) / ตามชื่อ — favorites จะลอยขึ้นบนสุดเสมอ
- **Attention lamps**: ชิปบนแถบด้านบนสรุปประเภทปัญหา (ไม่มี remote / detached HEAD / ยังไม่ push / ยังไม่ commit / behind / stash) คลิกเพื่อกรอง ทั้ง "Unpushed" และ "behind" ต่างมีปุ่มคลิกเดียวสำหรับ "push/pull all"
- **Grouping**: จัดกลุ่มตามโฟลเดอร์ / ตามภาษา / ไม่จัดกลุ่ม (แบบเรียบ)
- **Command palette ⌘/Ctrl-K**: ตัวเปิดโปรแกรมด่วน — พิมพ์ชื่อแล้วกด enter เพื่อเปิดใน editor (มีปุ่มย่อยสำหรับ terminal / folder / copy path / open remote)
- **Tag filter**: เลือกแท็กได้หลายรายการบนแถบด้านบน (แบบ AND — ต้องมีทุกแท็กที่เลือก) คลิก `#tag` บนการ์ดเพื่อเพิ่ม การกรอง + การเรียงลำดับ + การจัดกลุ่มจะถูกบันทึกร่วมกันเป็น "view" ที่ตั้งชื่อได้
- **Inline preview**: ปุ่ม "⋯" บนการ์ดจะแสดงคอมมิตล่าสุดแบบป็อปอัปโดยไม่ต้องเปิดแผงรายละเอียด
- **Auto-scan (ปิดเป็นค่าเริ่มต้น)**: มีสวิตช์ "manual ⟳ / auto ⟳" บนแถบด้านบน เมื่อเปิดใช้งาน ตัวเฝ้าดูไฟล์จะรีเฟรชการ์ดที่ได้รับผลกระทบให้อัตโนมัติ (มีช่วงพัก 60 วินาที การเปลี่ยนแปลงระหว่างช่วงพักจะถูกรวมไว้ ไม่มีการตกหล่น) เมื่อปิดใช้งาน สถานะจะอัปเดตเฉพาะตอนกด Rescan บอร์ดยังคงถูกเติมข้อมูลด้วยการสแกนครั้งแรกตอนเปิดใช้งาน
- **Scheduled fetch (ปิดเป็นค่าเริ่มต้น)**: "fetch: off / every 5–60 min" บนแถบด้านบน — ทำการ fetch remote ทุกตัวแบบพื้นหลังเป็นระยะ เพื่อให้ข้อมูล ahead/behind ทันสมัยอยู่เสมอ
- **18 ภาษา**: สลับภาษา UI ได้จาก ⚙ Settings (จีนตัวย่อ/จีนตัวเต็ม อังกฤษ ญี่ปุ่น เกาหลี สเปน ฝรั่งเศส เยอรมัน โปรตุเกส รัสเซีย อิตาลี อาหรับ ฮินดี เบงกาลี ไทย ตุรกี เวียดนาม อินโดนีเซีย) เมื่อเข้าใช้งานครั้งแรกโดยยังไม่มีการตั้งค่าที่บันทึกไว้ UI จะจับคู่กับภาษาของเบราว์เซอร์โดยอัตโนมัติ (กลับไปใช้ภาษาอังกฤษหากไม่ตรงกับภาษาใดเลย) ภาษาอาหรับจะสลับเป็น RTL โดยอัตโนมัติ เวลาสัมพัทธ์จะถูกแปลตามท้องถิ่นด้วย `Intl` โดยตรง ชื่อ repo คำอธิบาย และข้อความคอมมิตจะไม่ถูกแปลเสมอ

## Actions

- ส่วนท้ายของการ์ดจะแสดงปุ่ม editor / terminal / folder / copy-path เสมอ การเปิดปุ่มใดปุ่มหนึ่งจะบันทึกเวลา "last opened" ที่ใช้ในการเรียงลำดับ
- Fetch / pull (`--ff-only`) / push ทำงานเป็นชุด (batch): เลือกหลายการ์ด → ทำ batch-action จากแถบด้านบน หรือคลิกครั้งเดียวที่ไฟแจ้งเตือน "unpushed" / "behind" ทั้งหมด ความคืบหน้าจะแสดงแบบเรียลไทม์ หาก repo ใด repo หนึ่งล้มเหลว รายการที่เหลือจะไม่หยุดทำงานตาม
- **Run a command across repos**: เลือกการ์ด พิมพ์คำสั่งในแถบเครื่องมือ (เช่น `npm install`) คำสั่งจะรันแบบขนานในไดเรกทอรีของทุก repo ที่เลือก "Dry run" จะแสดงตัวอย่างก่อนว่า repo ใดจะได้รับผลกระทบ ส่วน "view output" จะแสดงผลลัพธ์รายตัวหลังรันเสร็จ
- **Stash inbox**: เมื่อมี stash หลงเหลืออยู่ที่ไหนก็ตาม ลิงก์ "stash inbox (N)" จะปรากฏบนแถบด้านบน — แสดงรายการ stash ทั้งหมดจากทุก repo พร้อม diff รายรายการ และปุ่ม `apply` / `pop` / `drop`
- การเลือกหลายการ์ดยังให้คุณ bulk-apply แท็กได้ด้วย
- **Manifest export / import**: ส่งออก manifest ของ repo ทั้งหมด (path + remotes + group + tags) จาก **+ new** เพื่อสำรองข้อมูลหรือย้ายเครื่อง การนำเข้าจะรับ repo ที่มีอยู่ในเครื่องแล้วกลับเข้ามาโดยอัตโนมัติ และแสดงรายการที่ยังไม่มีเพื่อให้ clone
- คำสั่งเปิดสามารถตั้งค่าได้ต่อเป้าหมายภายใต้ `open` ใน config.json โดย `{path}` จะถูกแทนที่ด้วย path ของ repo
- **+ New**: แนะนำเลขลำดับถัดไป (เช่น `028-`) และไดเรกทอรีแม่ของโปรเจกต์ที่มีเลขลำดับอยู่แล้ว จากนั้นสร้างโฟลเดอร์ รัน `git init` เขียนไฟล์ README และสแกนเข้าสู่บอร์ดใหม่

## Health checks & stats

- กฎต่าง ๆ (conflicted / no remote / detached HEAD / uncommitted / unpushed / untracked / behind / stash / stale) สามารถปิดใช้งานเป็นรายตัวได้ผ่าน `health.disabledRules` ส่วน `staleDays` กำหนดเกณฑ์ของสถานะ "stale"
- **Mergeable branches**: การ์ดจะแจ้งจำนวน local branch ที่ merge เข้ากับ HEAD ไปแล้ว (ไม่รวม branch ปัจจุบันและ main/master) แผงรายละเอียดมีปุ่มคลิกเดียวสำหรับล้างด้วย `git branch -d` (จะลบเฉพาะ branch ที่ merge แล้วเท่านั้น จึงปลอดภัย)
- **GitHub (ทางเลือกเสริม ผ่าน `gh` ที่ล็อกอินอยู่แล้วในเครื่อง)**: คิว "needs you" จะรวบรวม PR / issue ที่เปิดค้าง และ CI ของ default branch จากทุก remote ที่เป็น `github.com` แบบพื้นหลัง (มีการจำกัดอัตรา polling และบันทึกไว้บนดิสก์ เปิดใหม่ได้ทันที) แผงรายละเอียดยังสามารถสอบถามรายละเอียด PR ที่เปิดค้างและ CI run ล่าสุดได้ตามต้องการ คำอธิบาย repo จะถูกเติมย้อนหลังจาก GitHub เมื่อมีข้อมูล
- แท็บ **Stats**: heatmap คอมมิตข้าม repo ย้อนหลังหนึ่งปี (เฉพาะ local branch), repo ที่ใช้งานล่าสุด และ 10 repo ที่ไม่ถูกแตะต้องนานที่สุด
- แท็บ **Worklog**: เลือกช่วงวันที่เพื่อดูไทม์ไลน์คอมมิตข้าม repo (กรองตามผู้เขียนได้ — ค่าเริ่มต้นคือ "เฉพาะฉัน" โดยตรวจจับตัวตน git ของคุณโดยอัตโนมัติ) พร้อมปุ่มคัดลอกเป็นรายงานประจำสัปดาห์แบบ Markdown ได้ในคลิกเดียว
- คลิกการ์ดเพื่อเปิดแผงรายละเอียด แสดงสถานะสุขภาพแบบละเอียด, mergeable branches, **สลับ / สร้าง / ทิ้ง local branch**, **commit ในที่เดิม** (พิมพ์ข้อความแล้วสั่ง commit) พร้อม diff แบบเรียลไทม์ของการเปลี่ยนแปลงที่ยังค้างอยู่, GitHub PR/CI, heatmap ย่อ 12 สัปดาห์, คอมมิตล่าสุด, stash และ remote

## Organizing repos

- ติดดาว ★ ที่การ์ดเพื่อทำเครื่องหมายเป็น favorite (จะลอยขึ้นบนสุด) เพิ่ม/ลบแท็กได้ในแผงรายละเอียด (มีการเติมข้อความอัตโนมัติจากแท็กที่เคยใช้แล้ว) และเปลี่ยนกลุ่มได้ ("auto" จะคืนค่าการจัดกลุ่มตามโฟลเดอร์)
- **Notes / to-dos**: จดบันทึก "สิ่งที่ต้องทำต่อไป" ไว้ในแผงรายละเอียด — จะแสดงบนการ์ด
- **Exclude**: ซ่อน repo ที่ไม่ต้องการเห็น repo ที่ถูก exclude จะถูกซ่อนจากบอร์ด การแจ้งเตือน และ command palette โดยค่าเริ่มต้น "Excluded (N)" บนแถบด้านบนช่วยให้ดู/จัดการแยกต่างหาก (ยกเลิกการ exclude ได้จากแผงรายละเอียด)
- การเปลี่ยนแปลงมีผลทันทีและถูกเขียนลง config.json โดยไม่กระตุ้นให้เกิดการ rescan ของ Git

## Development

```bash
npm run dev     # runs server(7420) + vite(5173) together, frontend proxies /api
npm test        # full server + web test suite + both typechecks
```

Stack: Node + Hono (การเข้าถึง git ทั้งหมดผ่าน `spawn` ไม่มี native dependency), Vite + React 19 + antd 6 (ปรับแต่งเชิงลึกผ่านตัวแปร CSS), chokidar + WebSocket สำหรับการอัปเดตแบบเรียลไทม์

## Configuration (config.json)

| Field | Description |
| --- | --- |
| `roots` | ไดเรกทอรีรากที่จะสแกน ค้นหาไดเรกทอรีที่มี `.git` แบบเรียกซ้ำ (ความลึก ≤ 6) |
| `excludes` | ชื่อไดเรกทอรีที่จะข้าม (ค่าเริ่มต้นรวมถึง node_modules) |
| `manualRepos` | path ของ repo ที่เพิ่มด้วยตนเอง นอกเหนือจาก roots ที่ตั้งค่าไว้ |
| `tags` / `favorites` / `groupOverrides` | การตั้งค่าเฉพาะราย repo สำหรับแท็ก / รายการโปรด / กลุ่ม |
| `notes` / `archived` | บันทึกย่อ / สถานะเก็บถาวรเฉพาะราย repo |
| `health` | `{ staleDays, disabledRules }` |
| `open` | เทมเพลตคำสั่งสำหรับเป้าหมายที่เปิดด้วยคลิกเดียว (editor / terminal / explorer) |

ตัวแปรสภาพแวดล้อม `REPO_RADAR_CONFIG` สามารถใช้แทนที่ path ของไฟล์ config ได้ เซิร์ฟเวอร์จะรับฟังเฉพาะที่ `127.0.0.1` เท่านั้น และตรวจสอบ header Origin ทั้งบน API และ WebSocket
