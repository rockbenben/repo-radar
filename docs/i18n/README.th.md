# repo-radar

> โครงการ 365 Open Source #027 · แดชบอร์ดในเครื่องที่คอยเฝ้าดู Git repo ทั้งหมดของคุณ และบอกให้รู้ว่าอันไหนต้องการให้คุณจัดการ

[⬇ ดาวน์โหลดสำหรับ Windows · macOS · Linux](https://github.com/rockbenben/repo-radar/releases/latest)

คุณมี repo Git มากเกินกว่าจะจำไหวด้วยตัวเอง repo-radar เฝ้าดูทั้งหมดแล้วหยิบเฉพาะไม่กี่ตัวที่ต้องการคุณตอนนี้ขึ้นมา — ที่เหลือปล่อยให้หลุดจากหัวไปได้เลย

มันดึงสิ่งที่คุณมักลืมตรวจขึ้นมาให้เห็น:

- **งานที่ยังค้าง** — การเปลี่ยนแปลงที่ยังไม่ commit ยังไม่ push หรือค้างใน stash ถูกทำเครื่องหมายก่อนที่คุณจะทำหาย
- **GitHub กำลังรอคุณ** — PR ที่เปิดอยู่ issue และ CI ที่แดง อ่านผ่าน `gh` ที่คุณล็อกอินไว้แล้ว
- **โปรเจกต์ที่กำลังเย็นลง** — ไม่ได้แตะนานเกินไป หรือเลยกำหนดปล่อยเวอร์ชัน
- **repo ที่หลุดสายตาไปแล้ว** — ทั้งหมดอยู่ในหน้าจอเดียว ค้นหาได้ เปิดได้ในคลิกเดียว

อะไรที่ต้องลงมือจะลอยขึ้นบนสุดเป็นคิว หนึ่ง repo ต่อหนึ่งรายการ เรียงตามความเร่งด่วน กด ✓ เพื่อปัดออก แล้วมันจะไม่กลับมาจนกว่าจะมีอะไรเปลี่ยนจริง ๆ — มีข้อยกเว้นเดียว คือ stash ที่ปัดออกจะโผล่กลับมาอีกใน 30 วัน เพื่อไม่ให้ stash ที่คุณลืมจริง ๆ หายไปตลอด

## ขอบเขตที่รองรับ

| ด้าน | Windows | macOS | Linux |
| --- | --- | --- | --- |
| การติดตั้ง | ตัวติดตั้ง `.exe` | `.dmg` | `.AppImage` |
| ปิดหน้าต่าง | ย่อลงถาดระบบ | ย่อลงถาดระบบ | ปิดโปรแกรม — ใช้ **เริ่มเมื่อเข้าสู่ระบบ** เพื่อให้ค้างไว้ |
| การเฝ้าดูการเปลี่ยนแปลง | ทุก repo ใต้ไดเรกทอรีที่สแกน | เหมือนกัน | 200 repo แรก (ปรับเพิ่มหรือยกเลิกเพดานได้ในตั้งค่า) |

ทุกอย่างทำงานบนเครื่องคุณและใช้ `git` ที่คุณมีอยู่แล้ว — ไม่ต้องมีบัญชี ไม่มีการเก็บสถิติ ไม่มีอะไรถูกอัปโหลด ส่วนของ GitHub (PR, issue, CI) เป็นทางเลือกและอ่านผ่าน [`gh` CLI](https://cli.github.com/) ที่คุณล็อกอินไว้ ข้ามไปก็ยังใช้ส่วนที่เหลือได้

## การติดตั้ง

ดาวน์โหลดไฟล์ของแพลตฟอร์มคุณจาก [Releases](https://github.com/rockbenben/repo-radar/releases) — ไม่ต้องมี Node.js แอปไม่ได้เซ็นโค้ด แต่ละระบบจึงเตือนตอนเปิดครั้งแรก:

- **Windows** — ที่หน้าต่าง SmartScreen กด *ข้อมูลเพิ่มเติม → เรียกใช้ต่อไป*
- **macOS** — ครั้งแรกให้คลิกขวา → เปิด ถ้า macOS บอกว่าไฟล์เสียหาย: `xattr -cr /Applications/repo-radar.app`
- **Linux** — `chmod +x repo-radar-*.AppImage` ก่อน

ไม่อยากเชื่อไฟล์ไบนารีเฉย ๆ ใช่ไหม [คอมไพล์เองได้](../development.md) — แค่ `npm install && npm start`

เปิดครั้งแรกให้กด **เพิ่มไดเรกทอรีที่จะสแกน** แล้วชี้ไปยังโฟลเดอร์ที่ *บรรจุ* repo ของคุณ — เช่น `~/Projects` ไม่ใช่ทีละ repo มันจะไล่ลงไปลึกสุด 6 ชั้นเพื่อหาอะไรก็ตามที่มี `.git` แล้วกระดานจะเต็มขึ้นมาเอง ไม่ต้องยุ่งกับ JSON ไม่ต้องรีสตาร์ท

## กระดาน

หนึ่ง repo หนึ่งการ์ด — สีสุขภาพ สาขา รายละเอียด working tree ahead/behind commit ล่าสุด แท็ก — พร้อม **เอดิเตอร์ / เทอร์มินัล / โฟลเดอร์** ในคลิกเดียว

- **หาให้เจอ** — ค้นหา หรือกรองตามภาษา `#tag` หรือไฟสัญญาณ ⌘/Ctrl-K เปิดตัวเรียกใช้ด่วน
- **บันทึกมุมมอง** — ตัวกรอง + การเรียง + การจัดกลุ่มใด ๆ ตั้งชื่อไว้ใช้ซ้ำ
- **ทำทีละหลายตัว** — fetch / pull / push บน repo ที่เลือก หรือรันคำสั่งเชลล์เดียวกันในทุกตัว หนึ่ง repo ล้มเหลวไม่เคยทำให้ตัวอื่นหยุด
- **จัดการตรงนั้นเลย** — แผงรายละเอียด commit พร้อม diff สด สลับสาขา ทิ้งการเปลี่ยนแปลง เก็บกวาดสาขาที่ merge แล้ว และดึง PR กับ CI ของ GitHub เมื่อสั่ง
- **สร้างและย้าย repo** — **+ ใหม่** สร้าง repo แล้ววางลงกระดานทันที ส่วนการส่งออก / นำเข้า manifest พารายการ repo — เส้นทาง, remote, กลุ่ม, แท็ก — ข้ามเครื่อง

ไฟแถวบนคือชนิดของการแจ้งเตือน — ไม่มีรีโมท HEAD ลอย ยังไม่ push ยังไม่ commit ตามหลังรีโมท และ stash ค้าง ปิดอันที่คุณไม่สนใจได้ใน ⚙ ตั้งค่า

ยังมีอีกสองแท็บ: **สถิติ** (ฮีตแมป commit หนึ่งปี ตัวที่ขยันที่สุดและเงียบที่สุด) และ **บันทึกงาน** (คัดลอกช่วงวันที่เป็นรายงานประจำสัปดาห์แบบ Markdown)

ธีมห้องนักบินแบบเข้ม แปลเป็น 18 ภาษา และคอนทราสต์ของข้อความปรับตาม WCAG AA ทั้งธีมสว่างและมืด

## ทำให้ข้อมูลสดเสมอ

ค่าเริ่มต้นคือการสแกนซ้ำสำรองทุก 30 นาที บวกกับปุ่มสแกนซ้ำบนแถบเครื่องมือ การสแกนซ้ำอ่านเฉพาะสถานะ git ในเครื่องเท่านั้น — มันไม่เคยติดต่อ remote เพื่อล่าหาการเปลี่ยนแปลง

การสแกนอัตโนมัติด้วยการเฝ้าดูไฟล์ **ปิดไว้เป็นค่าเริ่มต้น** และเปิดได้จากตั้งค่า มันทำงานในเครื่องเช่นกัน แต่เมื่อมีหลายโปรเจกต์กำลังบิลด์พร้อมกัน บัฟเฟอร์การแจ้งเตือนของเคอร์เนลจะล้นตลอดเวลา และการล้นแต่ละครั้งแปลว่าเหตุการณ์ชุดนั้นหายไปจนเชื่อไม่ได้อีกแล้ว — คำตอบที่ปลอดภัยมีอย่างเดียวคือสแกนซ้ำอีกรอบ ซึ่งถูกคุมด้วย exponential backoff ให้ไม่เกินหนึ่งรอบต่อ 30 นาที แม้อย่างนั้นก็แพงเกินไปที่จะจ่ายตลอดเวลาสำหรับเครื่องมือที่ใช้ชำเลืองดูว่ามีอะไรเปลี่ยน เปิดแล้ว repo ที่เพิ่ม ลบ หรือเปลี่ยนชื่อจะปรากฏภายในไม่กี่วินาที

เปลี่ยนชื่อหรือย้าย repo แล้วแท็ก ดาว สถานะเก็บเข้าคลัง และโน้ตยังตามไปด้วย repo-radar จำ repo จากสิ่งที่อยู่ข้างใน ไม่ใช่จากที่ที่มันวางอยู่ โฟลเดอร์ที่ถูกย้ายจึงยังเป็นโปรเจกต์เดิม ไม่ใช่ตัวใหม่

การ fetch เบื้องหลังตามกำหนดเวลาเป็นทางเลือก และเป็นฟีเจอร์เดียวที่พูดกับ remote ของคุณด้วยตัวเอง คอลัมน์ GitHub คือสิ่งเดียวที่ออกสู่เครือข่ายตามนาฬิกาโดยไม่ต้องสั่ง: ตราบใดที่ติดตั้ง CLI `gh` อยู่ PR, issue และการแจ้งเตือน CI จะรีเฟรชผ่านมันทุก 12 นาทีและหลังการสแกนซ้ำแต่ละครั้ง ถ้าไม่มี `gh` หรือไม่มี remote GitHub แอปก็อยู่ในเครื่องล้วน ๆ

## ทำงานเงียบ ๆ อยู่เบื้องหลัง

ปิดหน้าต่างแล้ว repo-radar จะลงไปอยู่ในถาดระบบ **บน Windows และ macOS** การสแกนซ้ำ การเฝ้าดู และการแจ้งเตือน GitHub จึงยังทำงานต่อ ส่วนบน Linux การปิดหน้าต่างคือปิดโปรแกรม เพราะไม่มีถาดระบบที่เชื่อถือได้ บน Windows และ Linux คลิกไอคอนถาดเพื่อเรียกกระดานกลับมา ส่วนบน macOS ไอคอนจะเปิดเมนู ซึ่งมีคำสั่งนั้นเป็นรายการแรก — และเป็นที่มีคำสั่งออกจากแอปบนทุกแพลตฟอร์ม

ตอนปิด มันจะรองานของ git ที่กำลังทำอยู่ — pull ทีละหลายตัว หรือการลบ stash — ไม่เกิน 10 วินาที เพื่อไม่ให้อะไรถูกตัดกลางคันแล้วทิ้ง `.git/index.lock` ค้างไว้ ถ้ายังไม่พอ มันก็จะปิดอยู่ดีและบันทึกเรื่องนี้ไว้ในล็อก

เปิด **เริ่มเมื่อเข้าสู่ระบบ** แล้วมันจะเริ่มพร้อมเซสชันของคุณโดยไม่แสดงหน้าต่าง การแจ้งเตือนบนเดสก์ท็อปเป็นทางเลือกและจะดังเฉพาะตอนมีของ *ใหม่* เข้ามาอยู่ในรายการ GitHub ที่รอคุณอยู่ — PR, issue หรือ CI ที่ล้ม และไม่ดังตอนโหลดครั้งแรกเลย

## การตั้งค่า

ไดเรกทอรีที่จะสแกน โฟลเดอร์ที่ยกเว้น และคำสั่งเปิด แก้ได้ที่ ⚙ ตั้งค่า → การสแกนและคำสั่งเปิด ที่เหลืออยู่ใน `~/.repo-radar/config.json` ซึ่งคุณแทบไม่ต้องเปิด — ตัวเลือกที่เกี่ยวกับการแสดงผลล้วน ๆ (มุมมองที่บันทึก ธีม ภาษา และบันทึกกิจกรรม) อยู่ในพื้นที่เก็บข้อมูลของเบราว์เซอร์แทน รายการฟิลด์ทั้งหมด ไฟล์แคชที่อยู่ข้าง ๆ และตัวแปรสภาพแวดล้อมสำหรับรันอินสแตนซ์ที่สอง อยู่ใน[เอกสารอ้างอิงการตั้งค่า](../configuration.md)

## ข้อจำกัดที่ทราบ

- **การอัปเกรดเป็นแบบทำเองโดยตั้งใจ** ไม่มีอัปเดตอัตโนมัติ: รันตัวติดตั้งใหม่ทับตัวเก่า
- **การย้ายที่รอบสแกนจำไม่ทันจะเหลือข้อแนะนำ ไม่ใช่หายเงียบไป** เมื่อจับคู่อัตโนมัติไม่สำเร็จ การ์ดใบใหม่จะเสนอ *«น่าจะเป็นสำเนาที่ย้ายมาจากเส้นทางเดิม»* — กด **ย้าย** แล้วแท็ก ดาว และโน้ตจะตามมา ข้อแนะนำจะเกิดกับ repo ที่ถูกสแกนอย่างน้อยหนึ่งครั้งบนเครื่องที่ติดตั้งเวอร์ชันนี้เท่านั้น (บัญชีต้องมีบันทึก remote ของมัน) และจะไม่เกิดกับปลายทางที่คุณยังไม่ได้เพิ่มเป็นไดเรกทอรีสแกน
- **Linux ไม่มีถาดระบบที่ไว้ใจได้** ปิดหน้าต่างจึงเท่ากับปิดโปรแกรม
- **repo ที่คุณเพิ่มทีละตัวนอกไดเรกทอรีสแกน จะไม่ถูกจำด้วยวิธีนี้** — ถ้าย้าย คุณต้องชี้พาธใหม่เอง
- **การทิ้งการเปลี่ยนแปลงจะไม่แตะ submodule และ repo git ที่ซ้อนอยู่ข้างใน** และมันจะบอกตรง ๆ แทนที่จะรายงานว่าเก็บกวาดหมดแล้ว
