# repo-radar

> โครงการ 365 Open Source #027 · แดชบอร์ดในเครื่องที่คอยเฝ้าดู Git repo ทั้งหมดของคุณ และบอกให้รู้ว่าอันไหนต้องการให้คุณจัดการ

คุณมี Git repo เยอะเกินกว่าจะไล่ตามไหวด้วยตัวเอง repo-radar คอยเฝ้าดูให้ทั้งหมด แล้วหยิบเฉพาะไม่กี่อันที่ต้องให้คุณจัดการตอนนี้ขึ้นมาให้ — ส่วนที่เหลือจะได้ไม่ต้องมาคอยพะวง

มันช่วยเปิดให้เห็นสิ่งที่ปกติคุณมักลืมไปตรวจ:

- **repo ที่คุณลืมไปแล้ว** — ทุก repo ที่คุณเป็นเจ้าของอยู่บนหน้าจอเดียว ค้นหาได้ เปิดอันไหนก็ได้ด้วยคลิกเดียว
- **งานที่ยังทำค้างไว้** — การเปลี่ยนแปลงที่ยังไม่ commit ยังไม่ push หรือ stash ไว้ ถูกทำเครื่องหมายเตือนไว้ก่อนที่มันจะหลุดมือคุณไป
- **GitHub กำลังรอคุณอยู่** — PR ที่เปิดค้าง, issue และ CI ที่ล้มเหลวจากทุก repo รวบรวมผ่าน `gh` ที่ล็อกอินอยู่แล้วในเครื่องของคุณ
- **โปรเจกต์ที่กำลังจะร้างไป** — อันที่คุณไม่ได้แตะมานานเกินไป หรือเลยกำหนดที่ควรปล่อยรุ่น

อันที่ต้องลงมือจัดการจะถูกดันขึ้นไปไว้บนสุดของบอร์ดเป็นคิว เรียงตามความเร่งด่วน หนึ่งรายการต่อหนึ่ง repo — คลิกแล้วจัดการได้ทันที กด ✓ เพื่อเคลียร์ทิ้ง แล้วมันจะไม่โผล่มาอีกจนกว่าจะมีอะไรเปลี่ยนแปลงจริง ๆ และเมื่อไม่มีอะไรค้างอยู่ มันจะขึ้นว่า "all clear" ส่วน repo ที่เหลือ แค่ค้นหาก็เรียกดูได้เสมอ

## การติดตั้ง

ดาวน์โหลดไฟล์สำหรับแพลตฟอร์มของคุณจาก [Releases](https://github.com/rockbenben/repo-radar/releases) — ไม่ต้องมี Node.js เนื่องจากแอปยังไม่ได้เซ็นโค้ด แต่ละระบบปฏิบัติการจึงขึ้นเตือนตอนเปิดครั้งแรก:

- **Windows** — รัน `repo-radar-<version>-x64-setup.exe`; ที่หน้าต่าง SmartScreen ให้คลิก *More info → Run anyway*
- **macOS** — เปิด `repo-radar-<version>-arm64.dmg` แล้วลากแอปไปไว้ใน Applications ครั้งแรกให้คลิกขวา → Open หาก macOS บอกว่าแอปเสียหาย ให้ล้างค่า quarantine flag สักครั้งด้วย `xattr -cr /Applications/repo-radar.app`
- **Linux** — `chmod +x repo-radar-<version>-x86_64.AppImage && ./repo-radar-<version>-x86_64.AppImage`

หรือรันจากซอร์สโค้ด:

```bash
npm install
npm start
```

เมื่อเปิดครั้งแรก ให้คลิก **เพิ่มไดเรกทอรีที่จะสแกน** (หรือ ⚙ ตั้งค่า → ไดเรกทอรีที่จะสแกน) แล้วชี้ไปยังโฟลเดอร์ที่เก็บ repo ของคุณ — ไม่ต้องยุ่งกับ JSON ไม่ต้องรีสตาร์ท พอกดบันทึกมันก็สแกนใหม่ให้ทันที ส่วนการตั้งค่าเก็บอยู่ที่ `~/.repo-radar/config.json` เผื่อคุณอยากแก้เอง

## บอร์ด

หนึ่งการ์ดต่อหนึ่ง repo — สีสถานะสุขภาพ, branch, สรุป working tree, ahead/behind, คอมมิตล่าสุด, แท็ก — พร้อมปุ่มคลิกเดียว **editor / terminal / folder** บนทุกการ์ด จากตรงนี้คุณสามารถ:

- **ค้นหา** — ค้นหา, คลิกภาษา / `#tag` / ไฟแจ้งเตือนเพื่อกรอง, เรียงลำดับ และจัดกลุ่มตามโฟลเดอร์หรือภาษา; บันทึกการกรอง + เรียงลำดับ + จัดกลุ่มใด ๆ เป็น view ที่ตั้งชื่อได้ ⌘/Ctrl-K เปิดตัวเปิดโปรแกรมด่วน
- **ทำงานเป็นชุด** — เลือก repo เพื่อ fetch / pull (`--ff-only`) / push หรือสั่งรันคำสั่ง shell พร้อมกันทีเดียวทั่วทุกอัน (มีตัวอย่างแบบ dry-run ให้ดูก่อน และแยกผลลัพธ์ราย repo) ถ้า repo ใดล้มเหลว ก็ไม่ทำให้ที่เหลือสะดุดตาม
- **เจาะลึกเข้าไปใน repo** — แผงรายละเอียดให้สรุปสถานะสุขภาพแบบเต็ม, สลับ / สร้าง / ทิ้ง branch, **commit ในที่เดิม** พร้อม diff แบบเรียลไทม์, GitHub PR & CI ตามต้องการ, คอมมิตล่าสุด, stash, heatmap 12 สัปดาห์ และการล้าง branch ที่ merge แล้วแบบคลิกเดียวที่ปลอดภัย
- **อัปเดตอยู่เสมอ** — auto-scan แบบเฝ้าดูไฟล์เปิดไว้โดยค่าเริ่มต้น (ทำงานในเครื่องล้วน ไม่ใช้เครือข่าย) มีการสแกนซ้ำทุก 30 นาทีคอยเก็บตกเหตุการณ์ที่พลาดไป และมีข้อความ «สแกนล่าสุด» บนแถบด้านบน หากเกินขีดจำกัดการเฝ้าดู (ค่าเริ่มต้น 200 ปรับได้ หรือตั้งเป็นไม่จำกัด) จะเฝ้าดูรายการโปรดและอันที่คอมมิตล่าสุดก่อน ที่เหลืออาศัยการสแกนซ้ำ แผงตั้งค่าจะแสดงตัวเลขจริง «เฝ้าดู M จาก N» ส่วน fetch เบื้องหลังตามกำหนดเวลาต้องเปิดเอง มีแท็บ **Stats** (heatmap คอมมิตตลอดทั้งปี, ใช้งานมาก/น้อยที่สุด) และแท็บ **Worklog** ที่คัดลอกช่วงวันที่เป็นรายงานประจำสัปดาห์แบบ Markdown
- **เริ่มและย้าย repo** — **+ New** แนะนำโปรเจกต์เลขลำดับถัดไป, รัน `git init`, เขียน README และรับเข้าสู่บอร์ด; การส่งออก / นำเข้า manifest พาการตั้งค่าของคุณข้ามเครื่องได้

UI คือ antd 6 ในธีมห้องนักบิน (instrument-cockpit) แบบเข้ม แปลเป็น 18 ภาษา (จับคู่กับเบราว์เซอร์ของคุณโดยอัตโนมัติในการเข้าครั้งแรก, RTL สำหรับภาษาอาหรับ)

## ทำงานเงียบ ๆ อยู่เบื้องหลัง

การปิดหน้าต่างจะเป็นการย่อ repo-radar ลงไปพักที่ถาดระบบ (tray) โดยที่การเฝ้าดูไฟล์ การ fetch ตามกำหนดเวลา และการแจ้งเตือนจาก GitHub ยังทำงานต่อไป — คลิกไอคอนที่ถาดระบบเพื่อเรียกบอร์ดกลับมา หรือถ้าจะปิดจริง ๆ ก็สั่งออกจากเมนูของถาดระบบ (บน Linux ที่ถาดระบบบนเดสก์ท็อปมักไว้ใจไม่ค่อยได้ การปิดหน้าต่างจะกลายเป็นการออกไปเลย ให้เปิด เริ่มเมื่อเข้าสู่ระบบ ไว้แทน เพื่อให้มันเปิดค้างทำงานอยู่ตลอด)

เปิด **เริ่มเมื่อเข้าสู่ระบบ** ใน ⚙ ตั้งค่า แล้วมันจะเริ่มแบบไม่มีหน้าต่างพร้อมกับเซสชันของคุณ — ไม่มีหน้าต่างจนกว่าคุณจะเรียก การแจ้งเตือนบนเดสก์ท็อปที่เป็นตัวเลือกเสริมจะทำงานเฉพาะเมื่อมีอะไร *ใหม่* เข้าสู่คิวของคุณเท่านั้น แม้ปิดหน้าต่างอยู่ การอัปเกรดออกแบบให้ทำเองโดยตั้งใจ (ไม่มีอัปเดตอัตโนมัติ): แค่รันตัวติดตั้งใหม่ทับตัวเก่า ส่วนไฟล์ Log จะถูกเก็บไว้ที่ `<config dir>/logs/repo-radar.log`

## การกำหนดค่า

ทุกอย่างที่ UI แตะต้องจะถูกบันทึกไปที่ `~/.repo-radar/config.json` — คุณแทบไม่ต้องเปิดมันเลย ฟิลด์ที่สำคัญ:

| ฟิลด์ | หน้าที่ |
| --- | --- |
| `roots` / `excludes` / `manualRepos` | ที่ที่จะสแกน (ค้นหา `.git` ลึกได้ถึง 6 ชั้น), อะไรที่จะข้าม และ repo ที่เพิ่มนอกเหนือ roots |
| `health` | `{ staleDays, disabledRules }` — ปรับเกณฑ์ "stale" หรือปิดการตรวจสอบแต่ละอย่าง |
| `open` | เทมเพลตคำสั่งสำหรับปุ่ม editor / terminal / folder (`{path}` = path ของ repo) |
| `autoWatch` / `autoScanMinutes` / `watchLimit` / `autoFetchMinutes` / `notifications` | พฤติกรรมเบื้องหลัง — ค่าเริ่มต้นคือ `autoWatch` เปิด, `autoScanMinutes` เท่ากับ 30 และ `watchLimit` เท่ากับ 200 (0 = ไม่จำกัด) อีกสองตัวปิดไว้ |
| `tags` / `favorites` / `groupOverrides` / `notes` / `archived` | การจัดระเบียบราย repo |

`REPO_RADAR_CONFIG` และ `REPO_RADAR_PORT` (ค่าเริ่มต้น 7420) ใช้แทนที่ path ของ config และพอร์ต — ตั้งค่า **ทั้งสองตัว** เพื่อรันอินสแตนซ์ที่สองที่เป็นอิสระอย่างสมบูรณ์ เซิร์ฟเวอร์ผูกกับ `127.0.0.1` เท่านั้น และตรวจสอบ header Origin ในทุกคำขอ API และ WebSocket

## การพัฒนา

```bash
npm run dev     # vite + หน้าต่างแอปพร้อม hot reload
npm test        # ชุดทดสอบ server + web + desktop และการตรวจ type
npm run dist    # build ตัวติดตั้งไปที่ dist-electron/
```

Stack: เชลล์ Electron + Node + Hono (การเข้าถึง git ทั้งหมดผ่าน `spawn`, ไม่มี native deps) + Vite / React 19 / antd 6, พร้อม chokidar + WebSocket สำหรับการอัปเดตแบบเรียลไทม์ เซิร์ฟเวอร์ Hono ทำงานอยู่ภายในโปรเซสหลักของ Electron และหน้าต่างจะโหลดผ่าน `127.0.0.1` ดังนั้น UI จึงเป็น HTTP + WebSocket ธรรมดา — เหมือนกับที่จะเป็นถ้ารันในเบราว์เซอร์ทุกประการ
